# Poeticus 阅读入口与信息架构

> 产品结构说明，基于 2026-10-20 的实际首页和未实现方向整理。**现状**与**设计目标**分开记录；当前行为以代码、[首页架构](../architecture/home-screen.md)为准。导航阶段的施工与验收见 [#113](https://github.com/montricwang/poeticus/issues/113)。

## 读者在哪里做什么

| 位置 | 面向读者的职责 | 当前状态 |
| --- | --- | --- |
| **首页 Home** | 发现每日推荐；搜索作品；以后也可直接提出文学问题 | 每日推荐、竖排预览、作品搜索与转入阅读已实现；自由文学提问尚待 #351 验证 |
| **作品书库 Library** | 按作者、词牌或检索结果找到作品 | 作品目录和搜索已有；独立书库导航与作者页面仍是后续产品设计 |
| **阅读室 Reader** | 阅读某一作品正文，划选原文，进行上下文明确的伴读 | 阅读与讨论入口已实现，正文排版有独立行为约束；跨作品比较尚未作为产品流程验收 |
| **我的书房 Bookshelf** | 找回收藏、最近阅读、主动保存的札记 | 目标设计，尚未形成公开读者可用的完整闭环，任务归 #350 |

设计优先级是**作品与阅读成果**，而不是复制聊天产品的通用“项目树”。导航回答「我可以去哪」，作品列表/搜索回答「我可以读什么」；两者可以共享页面空间，但不要在领域模型中混为一物。

## 首页探索和阅读伴读

- 首页保留已经封板的每日推荐、作品搜索与动效；独立的文学提问入口是候选新增交互，不将一个输入框强制猜为万能搜索。
- 首页新建的自由讨论默认**没有当前作品**；阅读室的新讨论默认以当前词作与用户明确选区为上下文。可共享 Agent 与 Conversation 基础设施，但**不自动共享同一场会话或合并历史**。
- 如果用户从探索答案打开另一首词，应能够找到回到原讨论的路径；是否将当前讨论关联到新作品，应由用户明确决定。
- 书房中的收藏/札记由用户主动保存，不是聊天记录的另一种展示。未来删除讨论，也不能隐式删除独立保存的札记。
- 身份与私人会话同步属于 [#349](https://github.com/montricwang/poeticus/issues/349) / [#40](https://github.com/montricwang/poeticus/issues/40)，不为了画导航就虚构已存在的云端用户数据。

Conversation 的生命周期和当前本地存储见 [Conversation State](../architecture/conversation-state.md)；不要把「有历史」误认为「模型有长期记忆」。

## 手机、桌面与视觉约束

现有阅读导航、顶部开关和首页竖排应沿用 [前端视觉规范](frontend-visual-conventions.md)，不要因加入书房/自由提问便重排已确认的五列首页或随手改变印章、分割线和动效。

移动端「阅读／对话／赏析」的可达性由 #242 检查；已有局部入口上移不等于单行顶栏已经完成。未通过真实设备验收前，不写成已解决的手机交互问题。

## 阶段的结束条件

一次导航改版至少核对：从首页搜索/推荐进入作品、返回首页与目录、进入和退出讨论、保持当前作品/草稿、手机窄屏与桌面上路径可见、真实设备没有遮挡。视觉新想法可以明确不采用；无需为了关闭导航阶段而实现每种装饰候选。

设计讨论与历史来源保存在 [#113 的编辑记录](https://github.com/montricwang/poeticus/issues/113)，具体的排版/短评/导航实验分别按原生子 Issue 验收。
