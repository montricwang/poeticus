# Poeticus 前端视觉与排版规范

本文件记录**当前已确认的设计原则、参数入口、光学校正**。具体数值以代码为准；实现流程见[首页架构](../architecture/home-screen.md)，可复发错误见[编码经验本](../coding-lessons.md)。

## 一、区分四种性质

| 性质 | 例子 | 修改条件 |
| --- | --- | --- |
| 行为契约 | 竖排从右向左；禁止 CSS 裁半个汉字列；印章与诗文整体居中；分组优先截断；手机最多五列 | 修 Bug 不得同时改变，必须做客观回归 |
| 编辑设计 | 桌面题署分列；「节选」不带括号并置于标题下；标点居中与淡化；中国红克制使用 | 先经用户确认；不由 AI 擅自改审美 |
| 光学校正 | 作者相对标题下沉一个正文 em 再加 2px；印章上移一个正文 em；印章字形逐字横排堆叠 | 留语义变量和原因，换字体或字号后重新观察 |
| 实现 / 待验 | 1024px 断点、真实 Safari 差异、动效毫秒值 | 实际测量才算验收，不把临时方案写成美学规律 |

W3C [中文排版需求 CLReq](https://www.w3.org/TR/clreq/) 描述汉字竖排等基本方向；作者下沉距离、色彩、字距与编辑标记位置是本站的编辑决定，而非 W3C 强制格式。

## 二、样式参数的权威入口

| 领域 | 修改位置 |
| --- | --- |
| 明暗主题、印章中国红、圆角 | frontend/src/index.css 的 :root、.dark、@theme inline。引用竖线、链接、未读提示、错误语义色、印章与节选统一使用 --editorial-red；原色 --editorial-red-base = #AA381E，深色模式统一 75% 不透明度 |
| 装饰分隔线 | --editorial-divider-thickness；不代表所有边框必须使用相同厚度 |
| 首页正文大小、字距、印章字距、作者光学校正、宽度预留 | index.css 的 .home-recommendation-layout 与 .home-featured-poem |
| 阅读页主标题、正文、作者、小序的字级和行高 | index.css 的 .poem-reader；首页使用有范围的覆盖，不污染阅读页 |
| 印章字体和字形排布 | .home-read-seal、.home-read-seal-glyphs，苹果苹方优先 |
| 正文跨段距离 | --reader-source-gap-scale，同时被 JS 的宽度预算和 CSS 的块间距读取 |
| 桌面应用外壳、阅读页脚 | --desktop-shell-max-width、--reader-footer-max-width；阅读区列份额另用 --reader-column-share |
| 动效 | :root 的 --motion-*；首页动画的 HOME_*_MS 是 JS 的状态编排，必要时通过 CSS 变量传递 |
| 响应式与内容截断 | Tailwind lg 断点与 DailyRecommendation 的 matchMedia 要一致，具体断列在 FeaturedPoemDisplay |

### 中国红作为全站强调色

- 统一引用竖线（用户引用、AI Markdown 引用、编辑态引用）、链接、阅读区批注下划线、未读提示点及错误/重试提示的强调色，不再保留紫色与另一套报警红。
- **颜色与状态语义独立**：错误仍使用 Tailwind 的 destructive 语义和原有 role=alert；只把 --destructive 映射到统一中国红，不改变报错状态或按钮行为。引用和链接不被误认成错误。
- 色值只定义在 --editorial-red-base = #AA381E。浅色 --editorial-red 为原色 100%；深色 --editorial-red 为原色 75% 不透明度，**所有使用处统一**，包括印章边框/文字/悬停、引用竖线/下划线、链接、未读点与 destructive 错误提示，不再为装饰线另建一套透明度。引用正文继续用 text-muted-foreground。
- 引用竖线使用统一的 --editorial-red 参数；引用文字保留灰色。阅读区中已引用的原文在文字下方绘制细红线，入场时由左向右划出，取消引用即消失；不覆盖文字底色。此标记是独立叠加层，不改变正文 DOM 的字符顺序、复制或引用偏移。
- **不染红**正文、普通分割线、黑白主按钮或中性等待状态。红色负责强调，而不是覆盖所有灰阶。

## 三、首页有效的视觉规则

- **词牌**：桌面 36px、字距 0.08em（--reader-heading-letter-spacing），保持较强层次。
- **正文**：移动端 22px、桌面 24px；字距 0.12em，行高倍率 1.5。桌面每列 vertical-rl，容纳它们的父容器仍是普通横向 Flex。
- **作者**：桌面 18px、字距 0.10em；起始位置下沉一个正文 em + 2px。其中 2px 是视觉重心修正，调整 --home-author-optical-nudge，不当作布局补丁。
- **「节选」**：桌面及手机 24px，红色；桌面字距 0.12em，不加括号，放标题下方；作者独占相邻列。
- **阅读印章**：semibold、红边框红字；内部单字横排再纵向堆叠，间距 0.18em；整体上移一个正文 em，与正文组合横向间距 12px。
- **正文标点**：居中、弱化到前景色 20%，保留现有字形和书名线处理，不无故换成侧标点。
- **节选**：全词可容纳则显示全文；否则从首个 body_segments 分组起保留尽量多的**完整分组**；下一组不能完整容纳就停止，留白允许。只有首个分组也放不下才按完整诗句截断。数据库分组不一定对应词学的上/下片。
- **手机**：最多五列，不足五列时自然居中；题署不复用桌面双列方案；首页小序默认隐藏。

## 四、宽度与组件职责

1. DailyRecommendation 的推荐区负责提供可用物理宽度：减去印章、Flex gap、宽度安全预留。
2. FeaturedPoemDisplay 依据真实题署宽度、每列正文的实际行高判断保留的**内容**。
3. 标题、作者、正文各列自己竖排，父组件普通横向 Flex 按实际内容自然收缩；印章与整篇作品一起居中。
4. 不允许重新加入整篇竖排的离屏克隆、固定 article 宽度、Flex 二次收缩和 overflow-hidden 裁字等重复机制。

## 五、其他配置的盘点

本轮也统一了桌面外壳 1600px、阅读导航和阅读页脚共用的 27rem、首页搜索标题字距 0.12em。主题 token、阅读器 --reader-*、--motion-* 原来已集中管理，不新建平行配置系统。

**刻意保留局部的数字**：单个图标字号、焦点轮廓偏移、仅开发时显示的十词牌调试面板 420px、各动画关键帧的独有位移。只有后续出现第二个真实消费者才考虑抽成共享参数，避免变量泛滥。

## 六、施工和验收

1. 先判断问题属于行为错误、编辑设计还是光学校正，不把前者的修复当成重新设计的授权。
2. 调参前查 index.css 的对应入口，禁止 JS 和 CSS 对同一测量数字各维护一份。
3. 注释解释光学校正的**原因**；字体、字号改变后必须重新目测。
4. 客观约束交给测试：布局中心、12px 印章间距、完整分组节选、列宽与溢出。CI 和 Chrome 不能替代真实 iPad Safari 的字体、动画与触摸验收。
5. ADR 记录长期架构权衡，不为每个 px 建立。设计规范在本文件，实际配置在代码，错误复盘在 coding-lessons，未完成或试验性选择在 Issue。
