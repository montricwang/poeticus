# Poeticus 编码错误经验本

> 供 AI 开发协作者自行维护、下次施工前复习。这里只保存**能避免再次犯错的具体经验**；正式规范和检查命令仍以 [开发者指南](development.md) 与实际工具配置为准。

## 如何使用

1. **写代码前**：先快速阅读本文件，核对与本轮技术栈相关的注意事项；如有冲突，以当前源码、工具配置和明确需求为准。
2. **测试或 Review 后**：修复错误时，主动判断是否属于容易复发、难以当场发现或已有重复记录的问题。符合条件就新增或更新一条；普通笔误、无复用价值的偶发故障不抄录。
3. **优先落实自动防护**：能由 lint、格式检查、类型检查或回归测试捕捉的，就优先用工具约束；本文件记录检查入口和容易忽略的边界，不代替自动化。
4. **保持简短**：每条只写「现象／原因、下次怎么避免、如何验证」。修正规则或工具升级后同步更新旧条目，避免经验过期。**Warning 也要查看，但不能把所有 Warning 当成构建失败。**

## 已确认的经验

### Tailwind：ESLint 通过不代表类名符合规范

- **现象／原因**：项目启用了 `tailwindcss/enforces-canonical-classname`，当前配置级别为 `warn`；例如旧写法 `!mx-0` 可能被提示改为规范写法 `mx-0!`。`npm run lint` 即使退出码为 0，也可能存在警告。
- **下次避免**：编写或修改 Tailwind 类名时参照项目已有写法与当前 ESLint 配置，不沿用模型记忆中的旧版语法；不要为了绿灯盲目忽略规则。
- **验证**：执行 `cd frontend && npm run lint`，检查 **warnings 的内容**，尤其是本次变更涉及的行；需要修正时以当前插件给出的规范写法为准。

### Playwright：测试没有启动不能算通过

- **现象／原因**：曾因 WSL 缺少 Chromium Headless Shell，`npm run test:e2e` 在启动浏览器阶段失败，未执行到实际断言。
- **下次避免**：先区分浏览器安装／启动故障与业务断言失败；依赖不全时先核对 Playwright 浏览器安装状态，不靠修改测试断言掩盖环境问题。
- **验证**：执行 `cd frontend && npm run test:e2e`，确认用例真正启动且执行了断言；未能启动就明确记录「未验证」，不能写成 E2E 通过。

### 移动端视觉：模拟视口不能替代真实 Safari

- **现象／原因**：首页《杨柳枝》在 390×844 Chromium 模拟视口排成两行，而真实 iPhone Safari 曾排成三行；当时尚未取得足够真机布局数据，不能武断归因为断行算法。
- **下次避免**：先分开检查实际可视区域、CSS 盒模型和断行输入；避免为了模拟器中的结果不断追加评分特例。涉及平台差异时保留真实设备验收项。
- **验证**：分别记录模拟视口与真机的尺寸及可观察排版；只有真机检查过的行为才标为 Safari 已验收。

## 新增条目的最小模板

```markdown
### [模块／工具] 易复发的问题

- **现象／原因**：实际报错或不符合预期的表现，以及已核实的原因。
- **下次避免**：写代码前应该检查或采用什么做法。
- **验证**：对应命令、测试或真实操作；没有验证的部分写明未知。
```

历史经过、完整日志和临时试验继续放在对应 Issue／devlog，不在这里重复保存。
