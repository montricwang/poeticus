## 代码审查：哪些资料可能传到互联网

依据 `chore/public-deployment` 中的实际迁移、转换、API 代码，得到以下已验证事实：

1. `db/migrations/0001_corpus.sql` 至 `0003_yusheng_title.sql` 定义 `poems`（阅读作品）、`poem_source_texts`（私人来源证据）；没有 `annotations`、`commentary` 两列。
2. `scripts/corpus/adapter.py` 只将 `content.text`、`content.prefaces` 等转换为正式阅读字段；现代 `annotations/commentaries` 不进入这个转换所得的数据库记录。
3. `backend/corpus/repository.py` 的列表和详情 SQL **仅查询 `poems`**；详情 `body_segments`、`prefaces` 返回正文和词序，不查询来源证据表，不返回 `inline_notes` / `lacunae`。
4. **限制**：没有访问本地 3491 条真实数据的权限，尚不能断言每一条 `body_segments` 与 `prefaces` 均只包含公有领域原作文字；尤其来源 EPUB 的现代整理和标点等使用许可还应依据具体来源核对。字段名称不等于逐条版权保证；不存在逐条人工精校的证据。
5. 现有 `db_import.py --import` 会同时写 `poem_source_texts`，且插入新 UUID，故不适合作为云端公开读库迁移命令。
6. Railway Postgres 当前无公网 TCP 代理，可使用官方 CLI `railway connect Postgres --tunnel-only` 建本地临时 SSH 隧道。避免开放数据库公网端口与将私人词文提交公开仓库。

## 已实现但尚未真实跑源数据的迁移工具

[Draft PR #80](https://github.com/montricwang/poeticus/pull/80) 新增 `scripts/corpus/public_corpus_transfer.py` 和合成测试：

- 显式白名单：只读取并写入 `poems` 的十二列（含本地稳定 UUID、原序、词牌/标题、正文/词序、校审状态和版本），绝不复制 `poem_source_texts`、`inline_notes`、`lacunae`、现代 annotations/commentary。
- `--check` 离线于云端，批量验证数量默认 3491、唯一 ID、排序连续、非空正文、词序格式、质量状态及潜在现代编辑措辞；只输出统计与序号，不输出含全文的报告。
- `--apply --confirm-publish` 必须在用户本地由两条 DB 连接运行；云端必须已停止合成播种。事务只会删除精确识别的测试记录，且导入后用阅读字段 SHA-256 全量核对；发现未知记录或内容漂移即拒绝覆盖；重复运行内容一致则不重写。
- 使用官方 Railway CLI 隧道直接传输，不把原文 JSON 提交到 GitHub、聊天或第三方文件服务。具体 Windows PowerShell 步骤见 `docs/deployment.md`。

**证据等级**：源码字段审查 = 已验证；合成 CI = 待确认最终工作流；用户本地 3491 行预检、云端完整导入、分页搜索、内容许可 = 尚未验证。不能把脚本写好等同于已经发布作品。
