## 一、实际完成的功能

- 正式以 UUID 从 `GET /api/poems` 分页读取目录（作者、词牌、关键词筛选），选中作品后通过 `GET /api/poems/{UUID}` 获取 `body_segments`、`prefaces` 等详情；前端不再需要构建期预加载全部词文。
- 用户在 Windows 已验证本地 3,491 条目录、作品详情、翻页搜索、AI 聊天和刷新恢复。后续反馈逐步修复目录下拉混入「当前作品」、搜索闪动及 incipit 过长等问题。
- **阅读作品与目录结果独立：** 取消「当前作品」下拉框，搜索结果独立列表；浏览和翻页不强行更换正在阅读的 UUID 或对话，点击候选作品才切换。结果行仅列本页作品；目录加载时保留稳定的结果区高度。
- **目录短标签：** 有独立 `title` 显示词题；无词题则用词牌和正文开头至首个中文/英文句读（逗号、句号、问号、叹号、分号）前的文字区分同调作品，缺标点时限 18 个 Unicode 字符。显示裁切不修改语料正文。
- **文学题头层级：** 有 `yusheng_title` 时其为第一行深色 36px 主标题，原词牌 `cipai` 同字号淡色在后；无寓声则词牌为主标题。有词题 `title` 时下一行 18px；作者独立下一行 14px；`prefaces` 仍独立在正文前。例：**翦朝霞（主）　思越人（辅）／牡丹／贺铸**。源字段严格分离，未因展示反向污染数据库。
- **统一词牌筛选：** API `cipai` 参数保持不变，SQL 参数绑定条件为 `(cipai = %s OR yusheng_title = %s)`，支持与作者筛选组合；自由关键词 `q` 的字面匹配也涵盖寓声字段，统计总数和当前页使用同一过滤条件。
- 原文选区保持为浏览器单文本节点，发送给 Python 时将 UTF-16 偏移转换为 Unicode code point；旧 demo 会话不自动转给 UUID。增补 Python 合成 SQL 测试、前端 Node 测试及 CI lint/build。

## 四、从顶部搜索表单改为左侧可收起作品目录（#71 / Draft PR #72）

原先顶部横排的「关键词／作者／词牌」表单与整块搜索结果区占据了太多垂直空间。用户希望搜索退到左侧，阅读正文成为页面主体；作品一行一个标题也不足以辨认同调的多首词。这次不仅换了位置，还明确了查询规则与阅读状态的边界：

- **目录结构：** 桌面端左侧约 320px 的可收起目录，窄屏为有遮罩、Esc 与焦点处理的抽屉；目录独立滚动和分页。目录项改为两行，第一行「词牌·词题」加右侧作者，第二行首句，项与项之间使用细线；当前阅读作品另有低调标记。没有独立词题时，不再把首句伪装成标题。
- **寓声名展示：** 贺铸等有 `yusheng_title` 的作品，目录写作「**寓声（词牌）·词题**」，如「翦朝霞（思越人）·牡丹」；无题则不加中点。`cipai`、`yusheng_title`、`title` 仍分别保存在数据库，目录仅组合展示。
- **统一搜索框：** 不再要求分别填作者/词牌。按空白符拆成多个查询词，词与词之间为 **AND**，每个词可在作者、词牌、寓声、词题或正文中任一字段做字面子串匹配（字段间 OR）；不改变原有数据库 Schema。用户提到古文岛能让「虞美人春花」不加空格跨字段命中，但其实际算法并未查明，相关中文检索方案独立记 [#70](https://github.com/montricwang/poeticus/issues/70)，**本轮不承诺这种无空格跨字段匹配**。
- **状态约束：** 搜索、翻页不切换正在阅读的 UUID 或 Conversation。目录加载时保留旧列表，直到新结果返回，不再先清空目录制造闪屏。

用户 Windows 试用后又发现：点击新作品时原文和右侧聊天 Card 突然消失、重新出现。检查 React 代码发现旧实现会立刻调用 `setActivePoem(null)`。修复为**先请求新作品，成功后才一次性切换 UUID、正文与对应会话**；失败保留旧作品；连续点击会取消过时请求，防止内容错配。阅读器划词回调保持稳定，避免无关目录更新使选区事件反复订阅。

这部分是 [PR #72](https://github.com/montricwang/poeticus/pull/72) 的候选实现，**截至今晚仍是 Draft，未合并**，不能把所有视觉交互视为已验收。自动检查已通过多轮，仍需与真实浏览器里的动画感受分开描述。

## 五、侧栏动画、正文宽度和文字断行的实际教训（#73）

用户指出「侧栏收起太快、文字消失得比版面变化还早」，后又连续提交同一首《更漏子》在侧栏展开与收起状态下的截图，发现标题居中而正文明显偏左。逐项核对后区分出三个原因，而不是笼统地“加个动画”：

1. **侧栏与主区的宽度变化：** 桌面 Grid 从 `320px + 正文` 过渡到 `0px + 正文`，原先 200ms 的节奏偏快，改成 360ms 与统一缓动曲线；但目录自身还有独立的透明度淡出，导致文字提前消失，后来取消桌面端额外的 opacity 变化，让裁切跟随列宽一起发生。移动抽屉仍保持平移及遮罩过渡，尊重 `prefers-reduced-motion`。
2. **正文容器和正文文字不是同一个宽度：** `PoemReader` 先前在文章层有 `max-w-xl` 上限，主列扩张时正文不扩张；去掉该限制后，标题随全文宽度居中，但正文 `<p>` 仍从左边距开始，形成截图中的明显错位。随后将正文单文本节点所在容器调整为 `mx-auto w-fit max-w-full`，使**整块词文居中、内部仍左对齐**；并未把每行诗句分别居中。
3. **容器平滑，不等于文字换行平滑：** CSS 可以连续改变列宽，而汉字在临界宽度处会瞬间移到上一行或下一行；`w-fit` 的固有宽度也可能随断行变化，于是视觉上有跳动。单纯延长 transition 不能消除断行的离散变化；是否采用稳定阅读行宽，留待 [#73](https://github.com/montricwang/poeticus/issues/73) 继续结合实际词例讨论。

目前只调整视觉容器，**没有改 `poemText()`、原始字符串、单文本节点、浏览器 UTF-16 选区或发送 Python 的坐标转换**。用户指出「没有段首空两格」也属实：书籍模式此前明确暂缓，实现 #73 的居中并不意味着 #74 的排版模式已完成。

## 六、书页式三栏与无气泡阅读讨论的候选版（#63 / Draft PR #75）

用户进一步提出：不再用三个大圆角 Card 拼出软件面板，而用**左目录｜中正文｜右 AI 伴读**的细竖线划分空间；右侧讨论用文字层级、留白与短横线组织，像一本现代文学评论或校注书，而不是即时通信窗口。明确区分这种**纵向分隔线**与传统中文从右向左的竖排阅读（另属 [#29](https://github.com/montricwang/poeticus/issues/29)）。

从 #72 分支派生 `feat/editorial-three-column`，建立叠加的 [Draft PR #75](https://github.com/montricwang/poeticus/pull/75)，仅更改七个前端文件：`App` 的栏间细线，`PoemCatalog`、`PoemReader` 与 `ChatPanel` 去大 Card 外框，`UserMessage`／`AssistantMessage` 去读者气泡与 AI 星芒头像，`ChatComposer` 弱化外围边框。窗口不足以并排三栏时，伴读区移到下方。原文选区、SSE、会话恢复、编辑、复制、失败重试及重新生成的数据流程未重做。

**第一版实际试用随即发现视觉问题：**「读者」「AI 伴读」标签各占一行，正文又占一块，加上很多 `gap` 与 `space-y`，问答被拉得过于松散；目前短横线主要放在不同轮次之间，**没有按用户原意分隔同一轮里的读者与 AI**。复制、编辑、重生成按钮通过 `opacity-0` 隐藏，虽然不可见仍占有布局空间；原文引用仍留紫色小卡片，底部输入框也仍有圆角和边框。

晚上用户决定**只记录，明天再改**。后续候选是：角色标识紧贴首行或作为侧标；每轮问答内部使用短横线，轮次之间以更大的留白区分；操作按钮放在不额外占正文行距的位置，同时确保触屏可发现、键盘可达；原文引用回归中性细竖线，输入区可只保留顶部横线与清楚可用的发送按钮。去掉装饰性 Card 不等于取消必要的焦点、错误提示或可点击范围。上述反馈已记录于 [#63](https://github.com/montricwang/poeticus/issues/63)，**尚未编写第二版代码**。

## 七、未来阅读模式、版本边界和今日验收等级

三种横排模式已单独列为 [#74](https://github.com/montricwang/poeticus/issues/74)，**今天只记需求，不在 #72/#75 实施**：

- **书籍模式：** 自然段首行缩进两个汉字宽度，按普通书籍自然换行，片与片为正常段落距离；仅此模式有固定的段首两格。
- **分行模式：** 逗号、句号、问号、叹号后断行，顿号不断行；片间空行。以最长行决定整体文本块宽度，文本块居中，内部各行左对齐。
- **Python 模式：** 沿用分行规则；逗号后新行相对上一行多缩进一个全角空格，句号／问号／叹号后从首列重新开始；片间空行。缩进完成后，以整组行文最左与最右视觉边界计算居中，不是分别居中每一行。

后续实现不能把每个 `body_segments` 元素武断当成上下片；也不能向展示字符串随意插入全角空格、换行而不维护原文选区映射。当前用户更愿意先完成书页式视觉，三种阅读模式不成为此轮验收阻塞项。
