# Poeticus 开发日志｜2026-10-03

> **今日主线：** 在数据库与只读 API 接通后，以 Issue #68 / PR #69 将 React 的 14 首静态示例切换为本地 PostgreSQL 分页作品目录。用户 Windows 端反复实测，推动目录与阅读状态分离、题头按文学来源字段排版。本日志记录本次 PR 的工程取舍，真实语料字段问题仍留独立 Issue。

## 一、实际完成的功能

- 正式以 UUID 从 `GET /api/poems` 分页读取目录（作者、词牌、关键词筛选），选中作品后通过 `GET /api/poems/{UUID}` 获取 `body_segments`、`prefaces` 等详情；前端不再需要构建期预加载全部词文。
- 用户在 Windows 已验证本地 3,491 条目录、作品详情、翻页搜索、AI 聊天和刷新恢复。后续反馈逐步修复目录下拉混入「当前作品」、搜索闪动及 incipit 过长等问题。
- **阅读作品与目录结果独立：** 取消「当前作品」下拉框，搜索结果独立列表；浏览和翻页不强行更换正在阅读的 UUID 或对话，点击候选作品才切换。结果行仅列本页作品；目录加载时保留稳定的结果区高度。
- **目录短标签：** 有独立 `title` 显示词题；无词题则用词牌和正文开头至首个中文/英文句读（逗号、句号、问号、叹号、分号）前的文字区分同调作品，缺标点时限 18 个 Unicode 字符。显示裁切不修改语料正文。
- **文学题头层级：** 有 `yusheng_title` 时其为第一行深色 36px 主标题，原词牌 `cipai` 同字号淡色在后；无寓声则词牌为主标题。有词题 `title` 时下一行 18px；作者独立下一行 14px；`prefaces` 仍独立在正文前。例：**翦朝霞（主）　思越人（辅）／牡丹／贺铸**。源字段严格分离，未因展示反向污染数据库。
- **统一词牌筛选：** API `cipai` 参数保持不变，SQL 参数绑定条件为 `(cipai = %s OR yusheng_title = %s)`，支持与作者筛选组合；自由关键词 `q` 的字面匹配也涵盖寓声字段，统计总数和当前页使用同一过滤条件。
- 原文选区保持为浏览器单文本节点，发送给 Python 时将 UTF-16 偏移转换为 Unicode code point；旧 demo 会话不自动转给 UUID。增补 Python 合成 SQL 测试、前端 Node 测试及 CI lint/build。

## 二、明确暂不处理

- [#60](https://github.com/montricwang/poeticus/issues/60)：贺铸 `cipai/yusheng_title/title` 真实库值的核对；显示异常不等于数据库字段必然错误。
- [#67](https://github.com/montricwang/poeticus/issues/67)：纳兰词部分题序/正文误分类；不得把单份 JSON 数量通过当成文学语义已校勘。
- [#4](https://github.com/montricwang/poeticus/issues/4)：将来考虑独立侧边作品搜索栏、精细目录格式「词牌（寓声）·标题/首句」；现在不为了过渡性界面大改布局。
- [#40](https://github.com/montricwang/poeticus/issues/40)：对话从浏览器 localStorage 迁至 PostgreSQL，另起任务。

## 三、交付范围与验证等级

本轮 [PR #69](https://github.com/montricwang/poeticus/pull/69) 涉及前端目录/阅读器、后端只读筛选、UTF-16 选区转换、测试及架构文档。自动 CI 包含 Python 测试、前端 lint/build、Node 合成测试。用户确认搜索正常并授权合并；自动测试与用户抽样验证不等于真实 3,491 首逐条语义校对。

**安全边界：** 私有商业 EPUB、派生作品 JSON、个人校对文件和 DB 内容不进入公开 GitHub；本次只公开实现代码与人工合成测试数据。
