# Poeticus 开发日志｜2026-10-14（草稿：仅 Poem Retrieval／RAG）

> **待合稿，不是当日正式版。** 本文件仅收录这一轮对话完成的 Poem Retrieval／Werneror Corpus 组诗去重调查、实现与验收。当天另外两个对话仍在推进其他项目工作；后续编辑者请补齐其他部分，统一整理标题、导言与总评，再删除本提示。此稿不代表 10 月 14 日 Poeticus 的完整进度。

## 一、问题：相同诗句不等于作者重复创作

继续处理 [#151](https://github.com/montricwang/poeticus/issues/151)：陆游《鹧鸪天》（「懒向青门学种瓜」「片片轻鸥落晚沙」）作为当前作品时，原来的精确全文指纹过滤了独立《其六》，但语料里另一条题为《鹧鸪天 送叶梦锡》的 Work 实际拼接了七首词。Agent 只拿到候选作者、题目和命中 Chunk，没有合集的完整正文，于是可能将同一句误判为陆游在两首独立作品中重复创作。

这一轮明确分工：**检索层用原文与 Work ID 验证重复收录并过滤，Agent 负责比较真正不同作品之间的化用线索。** 用户决定不展示“所属组诗”字段：产品重点是化用关系，不是重建作品编排体系。

## 二、全量扫描、标题查漏与关系表封板

对 **853,385** 条 Werneror Work 逐一审计：同作者、同朝代、至少两个独立成员的完整正文顺序拼接，严格字面匹配找到 **75,327** 条合集。随后提取全部作品标题，调查「其一」「其二」「三首」「十首」「之几」、独立汉字数字等规律。典型案例表明成员题名往往有编号，合集题名却可能没有；七首陆游词合并 Work 竟沿用了第一首《送叶梦锡》的副题。另有《辋川集二十首》等**有系列归属、但未找到同名重复合集**的记录，不能误认为应删除。

允许忽略标点、空白和全半角差异后，仅新增 **6 条完整拼接合集、34 条成员关系**。另发现 **231 条**至少包含两个独立成员、却无法完整拼接的长记录，其中 **146 条**覆盖率达 80% 以上；它们可能夹题序或有缺漏，只列入待复核清单，不加入自动过滤。允许一两字不同的编辑距离方法也只用于发现疑似异文，不用来直接删候选。

最终形成 **75,333 条合集、269,556 条成员关系**。导出时重新逐条核对拼接，把 `parent_work_id`、`member_work_id`、序号、原文字符范围及关系类型保存到 `../poeticus-data/retrieval/relationships/v3/` 下的只读 SQLite、PostgreSQL 导入 CSV 和 manifest。Manifest 含 Corpus SHA-256、数量等校验信息。**没有改原始语料、Embedding 或索引，也没有向 Railway PostgreSQL 导入关系表**。检索 Work ID 与阅读库 UUID 分属两套身份。

## 三、检索逻辑：只排除有证据的重复合集

[PR #286](https://github.com/montricwang/poeticus/pull/286) 在 `backend/retrieval/poem/composition_filter.py` 实现可选过滤，在原 Eligibility 之后、最终 Top-K 之前查表，从候选池按原 RRF 顺序补位。当前 Work 已可靠识别时，只有本次合集命中片段也与当前正文重合才过滤；同次召回合集及独立成员时，只有二者证据片段重合才过滤。合集命中另一首成员、同作者同词牌、或标题相似，均**不足以自动删除**。

默认启动不会加载关系表；WSL 运行时必须显式指定 `--composition-db ../poeticus-data/retrieval/relationships/v3/work_compositions.sqlite3`。启动会核对来源指纹及关系行数，防止错用其他版本资产。不增添 Agent/HTTP 的组诗归属输出。

## 四、实际验收：从 8787 到 Poeticus 正式网站

CPU Qwen／FAISS／BM25 真实 A/B 覆盖陆游两句、杜牧《赠别二首》以及晏殊另一首《破阵子·春景》的反例。全仓 `pytest -q` **556 passed**，另有一条 LangSmith 上游弃用警告；PR 的 Ruff、BasedPyright 等 CI 均通过。PR #286 已 Squash Merge（`1e093a2`），采用英文 Conventional Commit。

最初检查发现早上启动的 WSL Retrieval 缺少 `--composition-db`，带鉴权搜索仍出现陆游《鹧鸪天 送叶梦锡》合集第 3。用户重启并添加参数后，再向真实 `127.0.0.1:8787/v1/retrieval/search` 发送四组带 Bearer Token 请求，全部 HTTP 200、均正常返回 Top-8；陆游／杜牧重复合集被排除，杜甫《小寒食舟中作》及晏殊独立作品保留。

Cloudflare 公网 `https://retrieval.poeticus.app/health` 返回 200。随后浏览器在正式 `https://poeticus.app` 打开陆游《鹧鸪天》，向 Agent 追问「片片轻鸥落晚沙」是否与前人诗句相似：`POST /api/chat/stream` 返回 HTTP 200，Agent 指出杜甫「片片轻鸥下急湍」是最强文本候选，没有再说陆游在另一首作品中重用此句；同时注明文本相似不等于已有文献证实有意化用。**未逐请求保存 Railway、Tunnel 与 WSL 的关联 Trace**，不把一次成功推断成长期可用。

完成现场验收后，[#151](https://github.com/montricwang/poeticus/issues/151) 已记录证据并关闭。Werneror 题名与正文错配见 [#173](https://github.com/montricwang/poeticus/issues/173)；少量异文、残缺或夹序合集是接受的覆盖边界，避免为追求百分之百召回不断扩张规则。

## 本轮 RAG 小结（供合稿）

我们解决的是**“语料库重复收录 ≠ 作者两次创作”**。利用离线关系表，在候选进入 Agent 前按可复核证据压制重复合集，避免误导化用分析；源语料和索引不动，缺乏高置信关系的情形宁可保留。该规则仅属于 Werneror Poem Retrieval，不能未经验证推广到未来古籍、词话或通用文本 RAG。
