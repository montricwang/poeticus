## 搜索结果页：从硬切换到重叠过渡

[Issue #308](https://github.com/montricwang/poeticus/issues/308)、[PR #318](https://github.com/montricwang/poeticus/pull/318) 使首页只有在**正式提交**搜索时才撤下每日推荐，输入草稿或键盘聚焦不会切换模式；搜索区上移，下方接原有分页结果，清除后恢复首页。结果标题复用 `poemLabel` 与目录字体，让「·」占一汉字宽度；同时补上手机目录抽屉漏用的题名字体。搜索框去掉浏览器自带的清除 X，只保留可访问的本站按钮。

动画经历了几个可以复现的反例：整页突然淡出、诗文在 opacity 结束前卸载、先等全部消失才启动搜索框、返回时搜索框与推荐重叠、只延长位移却忘记调整其他元素时序。最终采用**交叠过渡**：旧推荐保持原位渐隐，同时搜索区以 600ms FLIP 上移；清除时按真实几何让搜索框先越过诗文下缘，再让推荐竖列依阅读方向交错上浮，分割线最后从中央展开。搜索结果只让前八项错峰，避免二十条全部排队。修复 60ms 动画延迟期短暂闪到终点（WAAPI `fill: backwards`）以及桌面上浮过程生成临时竖向滚动条。没有引入新动画库。

## 首页与阅读室的首次入场

[Issue #319](https://github.com/montricwang/poeticus/issues/319)、[PR #321](https://github.com/montricwang/poeticus/pull/321) 在搜索过渡基础上补首次入场。首页等每日推荐及字体准备、布局稳定后播放：手机逐列从右向左，桌面按现有真实竖排行列顺序渐现；中间分割线从中央向两侧展开。发现**从阅读室点击「Poeticus」返回首页没有重播**后，取消跨页面的一次性限制，每次重新进入首页都会播放，但窗口 resize、主题和输入变化不会触发重播。

用户进一步确定搜索框要**最后出现**：推荐和中间线完成后，「美要眇兮宜修」先从下方轻微上浮，输入框与底部分割线延后 150ms 一起出现；等待期间搜索入口保持 `inert`，不接受误点与焦点。阅读室首次入场也为题头、正文及桌面伴读区安排克制的淡入；室内「上一首／下一首」仍使用原有作品切换过渡。减少动效偏好下直接展示内容。

## 测试反馈与下一步

按**客观 Bug、已有设计规范、尚未确定的审美选择**区分责任：交互失灵、瞬间闪动、临时滚动条、重复 X 和意外重播要由测试尽量提前检出；逐列节奏和文字气质由真实体验决定。测试聚焦开始、中途、结束、快速切换，以及手机与桌面代表尺寸，不遍历所有页面路径。新增浏览器 E2E 保护搜索与返回顺序、入场不重播及减少动效；本地因 Playwright Chromium 可执行文件不匹配，仍需要 GitHub Browser E2E 验证。今天收尾时还查到一项老 Node 测试硬匹配旧 `className`，随搜索区入场 class 变化报错，更新后恢复 **73/73** 通过。TypeScript、ESLint、Prettier 与生产构建通过。
