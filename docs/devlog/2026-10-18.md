# Poeticus 开发日志｜2026-10-18

## 首页与阅读室的入场节奏

延续昨日的首页动效，先修复 Safari 字体加载迟迟未完成时首页、阅读室保持透明的问题。[PR #324](https://github.com/montricwang/poeticus/pull/324) 为字体等待增加超时兜底，并为首页往返与直达阅读室补充浏览器回归。[PR #326](https://github.com/montricwang/poeticus/pull/326) 根据 iPhone、iPad 的真实使用反馈，把字体等待上限缩短到 **100ms**；首页竖排列、分割线、搜索标题、输入框和底部横线分阶段出现，阅读室入场节奏也进一步收紧。实际设备体验比原先更流畅。

关键教训是将**字体就绪、页面可见、动画起点**分别处理。字体慢加载不能长期阻塞页面；搜索区开始入场前需要完成前面的推荐与分割线，同时防止不可见输入框获得焦点。上述两份 PR 的相关 Node、类型、构建及浏览器 CI 检查通过；Safari 的最终观感以实际设备反馈为准。

## 桌面与 iPad 的竖排收口

[PR #328](https://github.com/montricwang/poeticus/pull/328) 整理了桌面推荐的竖排布局：标题、作者和正文列各自采用竖排，外层用普通 Flex 按实际内容自然收缩；「读这首词」印章与作品整体居中。节选优先保留完整 body_segments 分组，首组容纳不下时才按句界截取。

浏览器对十个真实词牌 × 五种桌面宽度进行了 50 组观察，检查横向中心、断列与窄屏节选。用户随后在真实 iPad 上确认新版布局与桌面一致，[#327](https://github.com/montricwang/poeticus/issues/327) 阶段性结案。[PR #329](https://github.com/montricwang/poeticus/pull/329) 把字号、字距、印章位置及作者光学校正集中到 index.css，并建立[前端视觉与排版规范](../design/frontend-visual-conventions.md)；[PR #330](https://github.com/montricwang/poeticus/pull/330) 同步清理首页架构的旧横向滚动说明。

## 中国红、原文引用标记与阅读室题署

[PR #331](https://github.com/montricwang/poeticus/pull/331) 将引用竖线、链接、未读提示与错误提示收敛到统一中国红 #AA381E，保留各自的状态语义。[PR #332](https://github.com/montricwang/poeticus/pull/332) 进一步统一深色主题的红色透明度：浅色保持原色，深色使用 75% 不透明度；阅读区已引用的原文增添 **2px 红色下划线**，从左向右出现，取消引用时消失。实现按叶子文本节点的 Range 计算并合并同一行片段，保留原文选区和复制的字符偏移契约。用户在本地浏览器确认视觉效果。相关 Node 78/78、构建、格式与 lint 检查已在 PR 中通过。

阅读室题头经数轮手动试排，最终保留思源宋体：作品标题 20px，作者和小序 16px，首页推荐与阅读室作者共用字重 **500**；题头间距分别为 **4 / 8 / 12px**，最后一个题头元素到正文 **24px**，手机和桌面采用同一组次级字号。[PR #333](https://github.com/montricwang/poeticus/pull/333) 已合并并更新视觉规范。这轮是用户直接验收的字体与间距微调，按约定省略测试。

iPhone 上另观察到：长按先自动选中一两个字，拖动系统选区两端手柄后，引用的红色下划线没有同步变化，点击周边空白处才更新到最终范围。现象及验收要求已加入 [Issue #86](https://github.com/montricwang/poeticus/issues/86)，与引用卡片文本更新时序一并排查。
