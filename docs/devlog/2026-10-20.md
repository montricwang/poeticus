## 《詩詞曲語辭匯釋》：私人语料采集与离线查询

为了更好解释柳永等词作中的旧白话、特殊词义与异形词，实际检查中国古典戏曲资料库的《詩詞曲語辭匯釋》。首页看起来是一篇长目录，实则指向许多 MediaWiki 词条；部分多义词页还以 `{{:词条/（一）}}` 引用更深一级的子页面。由此采用官方 Action API 获取各页**原始 Wikitext 修订**、递归展开分项，而非直接抓取渲染后的页面文字。

**已完成的可重复事实**：目录共有 539 项，其中 537 个语汇词头、另有敘言与跋；全站相关前缀分页遍历后，私人目录已保存 906 个原始源页面及 revision ID、编辑时间、固定旧版链接、SHA-256。递归覆盖校验：缺页 0。派生 SQLite FTS5 索引含 537 个完整词条，约 7.56 MiB；`PRAGMA integrity_check = ok`，可查「怎生」或以异形「折莫」定位「遮莫」，并回看原文书证及版本。离线测试 4 条通过。

**技术意外与边界**：WSL 对来源站点直连曾多次 TLS 失败，后来经浏览器同站 MediaWiki API 分批导出、Windows 下载目录中转至 WSL 私有目录，完成校验后清理中转文件。原始文本和数据库保存在 `~/projects/poeticus-data/lexicon/shi-ci-qu-yu-ci-hui-shi/`，不提交 Git、也不进入 Railway。数字化底本、用字准确度及公开再利用授权还需核实。本轮仅提供离线 CLI，不修改作品表与公开 Agent。

**本轮末讨论形成的后续产品方向（尚未施工）**：让 AI 阅读整首词，自行识别需要注释的词，不局限于词库收录的词头；对命中词返回全部可引用的义项与例证，读者自行比较，不强制模型唯一消歧。AI 补充解释必须与张相原书义项分开呈现。后续要验证漏注、过注、异形和语境中的歧义，继续在 [#335](https://github.com/montricwang/poeticus/issues/335) 推进。

工程记录：已合并 [PR #366](https://github.com/montricwang/poeticus/pull/366)，[本地数据说明](../data-management.md)、[词典工具说明](../../scripts/corpus/README-local-lexicon.md)。本段保留为合稿素材，可由负责正式 devlog 的对话继续整理。

## 《唐宋词鉴赏辞典》：全书 Critic 方法研究池完成（当日素材）

在 [#354](https://github.com/montricwang/poeticus/issues/354) 的前 20 篇手工实验基础上，多 ChatGPT worker 逐篇领取、研究《唐宋词鉴赏辞典》署名赏析；后期改为 **worker 只生成私有 JSON 草稿，主对话统一核对引文并提交**，避免多个 worker 对数据库/检查点并发写入。任务池提供单篇租约、令牌、原文坐标与 SHA-256 核验、拒绝重复写入和可恢复检查点。研究并非无人值守模型 API 批处理，也未证明文学解释全部正确。

**2026-10-20 收尾实测：**任务池 `done=1505, pending=0, leased=0`，`records/` 与 `cards/` 各 1505 份；其中最初 20 份是旧的 `moves` 格式、其余 1485 份为 `methods` 格式，跨篇处理需保留版本信息。额外 7 个 EPUB 分篇边界异常尚未纳入任务池，不能称为全书无漏篇。对私有 JSON 只读导出排序后的 `critic_methods_1505.jsonl`，保留原始独立卡，合计 7927 个方法动作记录与 23834 条证据索引；没有公开上传现代书籍赏析或研究卡全文。

为清理多人协作残留，在确认已无租约后，原 `results/inbox/` 的 21 个 worker/恢复子目录（3160 个文件，约 20.16 MB）整体移入 `results/archive/2026-10-20-worker-inbox/`，原目录重新置空；各人的草稿、token 与临时脚本仍可追溯但不作为正式成果使用。导出脚本与合成测试放在 `scripts/research/` 和 `tests/`，使用方式见 [私有研究卡导出说明](../../scripts/research/README-critic-methods.md)。

**后续（未施工）：**明天先检查原始卡的分析质量、跨篇标签的含义是否一致，再按实际论证动作提炼跨作者共有方法和代表性反例；在未见作品上比较基线 / 只增加证据 / 增加方法三组效果。不得把 1505 张卡的数量直接当作 Poeticus Critic 能力提升的证明；暂不引入线上 RAG、微调或复杂的自主研究架构。

## Critic 知识分层、记忆与“审美种子”：今日讨论，未施工

- 区分三个独立维度：**保存的内容**（原文/评论家观点/可迁移方法/Poeticus 自己的判断）、**数据对象及归属**（Document、Claim/解释、Method、Notebook、版本化 Persona）、**运行时使用方式**（Prompt、RAG、按需 Skill、工具）；**RAG 不等于知识类型，Skill 也不等于方法数据库**。
- 观点/札记允许**多对多**关联多个原文位置、支持与反例；链接目标应是带来源版本及稳定位置的 Canonical Document，不是重分片后可能变化的向量 Chunk。评论者说法与模型自己的判断必须区分；可修订但不覆盖历史。
- 复查 [#148](https://github.com/montricwang/poeticus/issues/148)、[#311](https://github.com/montricwang/poeticus/issues/311)、[#347](https://github.com/montricwang/poeticus/issues/347)：已有 SQLite 追加式事件记录隔离原型 [PR #348](https://github.com/montricwang/poeticus/pull/348)（**未合并、未接 Agent**）。下一轮先比较 LangMem/Mem0/Hindsight 的最小读写、修订、撤回、检索和迁出成本，不安装所有框架。
- **访谈式初始审美画像（候选）**：私有历史诗词/和歌对话 + 有针对性的作品对照访谈，提炼“用户明确表述/研究者推测/待确认”三类审美种子；严格征得用户确认，不把私人聊天写进公开仓库，也不把创始人偏好当客观文学事实。
- **MAGI 三视角（候选）**：同一 Agent、同一 Library/Notebook 可按需采取考据（证据）、审美（表现机制）、质疑（反例）三种立场，再综合；先用单次三视角提示验证，之后才考虑 3+1 次模型调用，对照质量与 tokens；**不预设三个独立 Agent / 三套记忆**。
- **后续优先级未变**：先完成 [#311](https://github.com/montricwang/poeticus/issues/311) 的独立判断/文风 MVP 与 [#341](https://github.com/montricwang/poeticus/issues/341) 的 3–5 段质量实验，再做 [#312](https://github.com/montricwang/poeticus/issues/312) 初始自主阅读和 [#314](https://github.com/montricwang/poeticus/issues/314) 对照评测；不要用“让模型对话几千轮”替代记忆持久化和评测。
