## 一、把目录作为独立的弹性布局，而不是不停调整像素

继续验收 10 月 14 日开发的桌面双栏阅读和目录。在 **1200px 最大版心**下，左侧阅读约 **500px**，中间分割线与间距合计 **50px**，右侧讨论／赏析／目录约 **650px**。目录使用右侧现成辅助区，切换目录时不挤压左侧阅读区；桌面可以连续选诗，移动端选诗后仍关闭抽屉。桌面页头把目录入口放在右上角，按钮显示图标与「目录」文字，收起目录使用向上的 `ChevronUp`。

借助 React Developer Tools、VisBug 和浏览器真实盒模型尺寸，重新区分 React 组件边界、DOM 元素与 CSS 布局职责：`ReaderCompanionLayout` 管双栏及中线；`PoemCatalog` 内部分为标题、搜索、独立横线、作品列表和分页。标题／搜索高度主要由内容决定；横线两侧留适度可伸缩间距；**作品列表使用 `flex-1` 消化剩余空间**，根据列表实际高度与当前 **56px 行高**计算每页条目，而不是让空白任意堆在分割线上。目录下方分页保留独立横线。长词题截断，桌面条目用题名、首句和作者共同定位作品；移除了不必要的首句悬停提示。手机仍保留原有更紧凑的目录样式。

## 二、诗词阅读页：偏上、居中与小序的取舍

短词过少时，原来的垂直居中让书页显得不够稳；但左侧不应逐首追随右侧空对话区的位置。于是给 `PoemReader` 的原有内容容器加 CSS 伪元素，让正文以外的剩余高度按**上方 42%／下方 58%**分配：短词略偏上，长词自动挤掉留白并正常滚动。没有新增 React 布局组件，也不更改诗句本身的行高和字距。

使用 VisBug 检查《扬州慢》时发现阅读滚动区原来只在右侧预留 **8px**，导致标题和正文的中心比底部分割线、翻页导航偏左约 **4px**。改为左右各 **4px**，让词题、作者、底部分割线和「上一首／下一首」真正共用阅读区水平中心线；手机阅读同样不横向溢出。

小序最终采用**最大 400px 的居中版心、`width: fit-content`、多行正常左对齐、浏览器自然换行和 `1.7` 行距**：一行短序的文字本身居中，多行长序左对齐且自动换行，手机按较窄的可用宽度排版。中间试验过 `text-wrap: balance`、收窄到 `26em`、以及按 `Range.getClientRects()` 检查换行后施加 `text-indent: 2em`。后者虽可在桌面／手机根据实测行数切换，但《扬州慢》出现孤零零的末行「也。」，增加了复杂度又未改善体验；**最终移除条件缩进组件及其测量逻辑，也撤销均衡换行**。取舍是保留书卷气但不机械复制纸书段落格式。

## 三、排版验收与交付证据

在本地 Vite 浏览器多轮检查了短词／长词的垂直位置、目录开关与连续选诗、作品列表条目、左右版心、长小序／短小序，以及 **390×844** 手机视口；最终重新验证桌面打开目录后选择《菩萨蛮》，目录保持打开、标题与底部分割线的中心一致，手机端不横向溢出。用户通过多轮截图参与取舍，决定这一轮视觉调整停止，不再追逐逐首词的像素级对齐。
