# 首页推荐作品：移动端竖排布局

本文记录 2026-10-17 经 iPhone 真机观察后暂时封板的首页推荐布局。具体试验与未完成项见 [Issue #302](https://github.com/montricwang/poeticus/issues/302)。本规则仅适用于首页推荐，不改阅读室的全文展示。

## 手机竖屏的布局原则

- 顶部导航、推荐槽位、分割线与底部搜索入口构成纵向布局。搜索入口保持靠近屏幕下方；推荐槽位使用剩余高度，而非用固定高度挤压文字。推荐、分割线、搜索之间由父级间距控制。
- **印章与作品作为一个视觉整体水平居中**，不是只把正文放在中心再把印章孤立贴到左侧。两者保持约 12px 的呼吸间距；正文区域仍要留出安全边距。
- 短词按内容自然收起，在推荐槽位中留白；不把所有作品强制拉到同一高度或宽度。

## 正文篇幅与断列

- 手机首页**正文最多五列**。五列是上限而非目标；还要服从屏幕实际横向空间与纵向可用高度，小屏可能只有两至四列。
- 不以“小令 58 字”为硬门槛，也不增加独立的纵向字数上限。更高的手机可以在五列内显示更多字，**不同手机不要求截取同样多的文字**。
- 优先显示全词；若全词不能在当前预算内排下，依次尝试完整的第一片、第二片及后续片段。后续片段必须整体容纳才加入，不从第二片中间随意截一段。若第一片也容纳不下，优先在可以容纳的完整句末截取，并显示「节选」。阅读室始终保留原文全文。
- **节选判定与最终断列共用同一套预算和排列逻辑**。离屏测量也必须使用首页实际的高度 CSS 变量，避免测量元素失去上下文后误判《青玉案》需要截断。

## 代码位置

| 文件 | 职责 |
| --- | --- |
| `frontend/src/components/home-screen.tsx` | 首页纵向空间分配、推荐高度预算、搜索入口及开发环境调试入口 |
| `frontend/src/components/daily-recommendation.tsx` | 组合印章与诗文，控制整体视觉居中 |
| `frontend/src/components/featured-poem-display.tsx` | 根据可用高度和五列上限选择展示片段，调用断列并标记「节选」 |
| `frontend/src/lib/home-preview-columns.ts` | 断列算法，偏向完整句读和避免孤字 |
| `frontend/src/index.css` | 竖排正文、列间距与 CSS 高度约束 |

本轮只封板**手机竖屏的视觉方案**，不将实验参数推广到桌面或阅读室。开发环境的十首词牌切换器仅供排版检查，不能进入生产页面。

## 验证与后续边界

2026-10-17 以 iPhone 17 真机查看十首代表性作品后，用户接受了当前竖排观感，并明确要求停止继续调整算法。模拟测试还覆盖 320×640、390×844、402×874、430×932 等视口；常规尺寸的正文不超过五列。自动化检查与实际视觉验收分别记录，不互相替代。

**暂缓处理而非视为全部通过：** 极窄且极矮视口的水平溢出、手机横屏降级、641–1023px 过渡布局及搜索提交后的页面状态。重新开启调整应有具体用户反馈或失败 Case，不为追求所有机型统一而主动增加排版规则。
