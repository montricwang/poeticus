# 首页：每日推荐的布局与预览规则

本文只记录当前首页的有效实现。 视觉参数和审美/行为区分见 [前端视觉与排版规范](../design/frontend-visual-conventions.md)。10 月 17 日的试验与封板过程见 [Issue #302](https://github.com/montricwang/poeticus/issues/302)；阅读室排版是独立职责，不应照搬首页截断规则。

## 组件与数据

- `frontend/src/components/home-screen.tsx`（`HomeScreen`）：组合导航、推荐槽位、分割线和馆藏搜索；通过 `ResizeObserver` 测量推荐槽位，将剩余高度写入 `--home-classic-max-height`。每日推荐由上游 `featured` 提供，首页不生成另一套推荐或会话。
- `frontend/src/components/daily-recommendation.tsx`（`DailyRecommendation`）：排布印章与作品，印章点击后进入阅读室。手机端沿用已封板的印章跟随正文左缘定位；桌面端以 Flex 将「印章＋真实诗文宽度」整体居中。
- `frontend/src/components/featured-poem-display.tsx`（`FeaturedPoemDisplay`、`ContinuousPoemBody`）：根据空间决定预览哪些完整片段，并将手机正文断为竖列。纯文本列划分由 `frontend/src/lib/home-preview-columns.ts` 的 `arrangeHomeColumns` 负责。
- `frontend/src/components/home-search.tsx`：馆藏搜索独立于每日推荐；未提交搜索时搜索区靠近首屏底部，提交后切换到结果视图。

正式首页不提供样本切换按钮；仅在 Vite 开发环境的桌面首页右下角提供十个词牌的临时排版样本入口，通过现有馆藏 API 读取真词，点击「恢复今日推荐」回到每日推荐。生产构建不显示这一入口。

## 首页搜索模式（Issue #308）

- `filters.q` 是**已提交搜索**的权威状态；输入框的 `query` 只是未提交草稿。聚焦或输入不会切换首页模式，也不会主动隐藏每日推荐。
- 提交非空搜索时，搜索入口立即进入结果布局并从原位置开始 FLIP 上移；推荐及中间分割线保留为原位置的固定退场层，淡出后卸载，不参与新布局。结果列表随后出现；首页滚动位置归零，不调用 `scrollIntoView`；提交同时失焦协助关闭软键盘。
- 点击结果区的「清除搜索」同时清除草稿和已提交过滤条件，恢复原始首页；搜索框 `autocomplete="off"`，用 `type="text"`、`role="searchbox"`、`inputMode="search"` 和 `enterKeyHint="search"` 保留搜索语义及移动键盘搜索键，避免浏览器原生 X 与本站自定义清空按钮叠加；不实现站内历史记录。浏览器是否完全遵守该属性由浏览器决定。
- 搜索/清除共用 600ms 减速 FLIP。提交搜索时，推荐文字约 330ms 淡出的同时搜索框已经上移（起步延后 60ms），中间分割线先淡出，结果列表前八项依次 Fade Up。清除搜索时，搜索框立刻下移；实际越过诗文下缘后，推荐逐列从右往左 Staggered Fade Up（270ms/列、间隔 42ms），中间分割线最后以 Line Reveal 从中心向两侧出现。短词/长词使用真实几何判断，避免过早重叠；`prefers-reduced-motion` 下直接呈现。#319 的搜索结果与清除后推荐入场在 #308 的搜索分支完成；首次进入首页、从阅读室返回首页与阅读室本身的入场由独立 PR #321 实现。
- 首页结果标题和阅读室目录共同使用 `poemLabel` + `.poeticus-catalog-title`，让题名中的间隔号 `·` 使用思源黑体并占一个汉字宽度。由于首页为宽列表、阅读室目录是侧栏，不直接共用整张列表的 UI。
- 进入首页，在推荐词及字体准备完毕、浏览器完成至少两帧布局后才开始入场：手机逐列 380ms/70ms，桌面按当前 DOM 真实行列顺序逐项展开（不修改断列）；分割线最后从中间向两侧展开。每次从阅读页返回首页也重新播放入场（首页组件重新挂载）；搜索区在推荐与中间分割线完成后按 Staggered Fade Up 入场：「美要眇兮宜修」先从下方 14px 上浮淡入，输入框与底部分割线延迟 150ms 后一起从下方上浮（各 420ms）；等待期间保持 inert 防止不可见的输入接收焦点。窗口尺寸、主题和搜索输入变化不重复播放。若推荐加载失败或用户启用减少动效，搜索区立即可用。
- 搜索框延迟 60ms 的 WAAPI 动画使用 `fill: backwards` 保持原位置，消除顶部瞬间闪动；推荐桌面横向滚动容器禁止纵向滚动，避免文字 `translateY(6px)` 入场时出现临时滚动条。回归需检查中间帧，而不是只看最终布局。
- 进入阅读室时，题头先淡入，左侧正文按行逐项 Fade Up，右侧伴读区轻微淡入；普通阅读室内换诗仍沿用现有 360ms 的淡出/淡入，若在首次入场期间换诗则直接转入普通切诗过渡。直达 `#reader` 同样支持首次入场；`prefers-reduced-motion` 时直接呈现。
- 手机 Safari 实际软键盘与滚动行为仍须单独验收，不以桌面模拟取代。

## 已封板的手机竖屏设计（2026-10-17）

- 推荐槽位利用导航与底部搜索区之间的可用高度；推荐区、分割线和搜索区的间距由父级 `gap-4` 统一管理。推荐区不覆盖搜索，也不用 `position: fixed` 把搜索强行钉住。
- 作品和左侧「读这首词」印章作为一个整体水平居中，保留屏幕边缘安全留白；短作品自然收窄并留白。
- **正文最多五列**（`HOME_MAX_BODY_COLUMNS = 5`），不为填满而强制排成五列；设备实际宽高、标题和分片间距可以进一步减少列数。五列不是字数上限，也不按“小令 58 字”机械截断。纵向只受推荐槽位的实际高度预算约束。
- 优先展示全词；不够容纳时按顺序尝试完整的首片、后续完整片段。第一片仍无法容纳时，才向下取到可容纳的句号（`。！？`）等句界；确实放不下时存在更细的退路。被截断时标注「节选」，阅读室始终使用全文。
- 列数和节选**必须使用同一套物理预算与断列规则**：`getHomeMobileColumnBudget` 与 `arrangeHomeColumns`。不可用另一套宽度估算独立决定是否节选，避免出现可完整显示却被误判的情况。
- 当前移动断列模式以 `<1024px` 判断；这只是现行实现，不表示所有平板宽度及横屏已完成独立验收。桌面沿用另一种逐句竖排方式。

上述取舍已在 iPhone 17 上获得用户的阶段性视觉认可，不再继续主动调节正文列数、纵向字数或断列代价。**这是手机竖屏的阶段性封板，不是对所有极小屏、横屏或浏览器环境的全面验收。**

## 桌面与 iPad 横屏的宽度约束（2026-10-18）

- `>=1024px` 采用桌面逐句竖排。推荐区真实宽度减去印章、12px 间距及安全余量，得到唯一的诗文宽度预算；不把 `w-max`、滚动窗口的收缩结果当作另一份预算。
- **桌面排版结构**：诗文最外层保持普通的 `horizontal-tb` 横向 Flex（`row-reverse`）；只有标题列、作者列与每条正文列独立使用 `writing-mode: vertical-rl`。每条正文列的物理宽度明确为 `font-size × line-height`；整个「印章＋诗文」自然按内容收缩并共同居中，印章与诗文保持 12px 间距。不要再给整个竖排 `article` 赋予测量得来的固定宽度——此前 Safari 在这一步出现与 Chrome 不同的布局结果。
- 桌面 JS 只读取页面实际题署宽度与正文计算后的 `line-height`（每个 `.poem-reader-line` 的横向步长），加上分段间距来决定最多放几列。最终 DOM 自身的横向 Flex 自然计算宽度；不再克隆整首 `vertical-rl` 文章到 `document.body` 做第二次宽度测量，也不用 `overflow-hidden` 兜底裁字或横向滚动。
- 全文可放下则展示全文；超出时按 `body_segments` 的原有分组顺序只保留尽量多的**完整分组**，下一分组放不下就停止，允许留白。仅当首个分组也放不下时才退回按完整视觉诗句截断，并标记「节选」。不再跨分组逐句补满。`body_segments` 不保证等同词学意义上的上下片。
- 桌面首页题署与移动题署独立：主标题/词题、作者分列，桌面小序隐藏，阅读室保持全文；手机仍使用最多五列的原有断列规则。
- 2026-10-18 已在 Chromium 的十个真实词牌 × 1024/1194/1280/1440/1920px 共 50 组确认水平居中、无截列和随宽度增加不丢列；移动端 320/390/402/430/820/1023px 做过三个作品的浏览器回归。**iPad Safari 真机仍需复验**，见 Issue #327，不能用 Chromium 模拟代替真机结论。

## 验证与已知边界

- 典型验证：手机宽度 320、390、402、430px，分别检查小令、中调、长调等十首样本；确认正文列数、全词或「节选」、印章加正文的中心位置，以及搜索区位置与横向溢出。桌面另行核对。
- 曾在 402px 手机视口发现《青玉案·元夕》误标「节选」：离屏测量克隆脱离 `#home`，丢失高度变量而误用较小的默认高度。修复措施是为克隆同步实际高度预算、去掉克隆时的旧高度，并在预算变化时重新测量。
- 317×446 等极小尺寸及横屏的推荐区/搜索区布局仍可能溢出，按 [Issue #302](https://github.com/montricwang/poeticus/issues/302) 或后续专门任务追踪，不把阶段性封板解释为已解决这些问题。
- 检查命令见 [开发者指南](../development.md)。自动检查、桌面 Playwright 不能代替真实 iPhone Safari 的视觉验收。
