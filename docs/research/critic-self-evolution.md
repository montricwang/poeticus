# Poeticus Critic：自主研究与审美演化（研究设计）

状态：长期研究方向尚未完成质量验证；已有隔离原型不代表产品实现。初版：2026-10-17。源头：#148。

> **2026-10-19 阶段更新**：当前 Critic 的执行优先级以 [#311](https://github.com/montricwang/poeticus/issues/311) 为准（先独立判断与文风，再证据与 Notebook 实验）。本地 4B/8B/27B 推理与短性能测试已完成，见 [#339](https://github.com/montricwang/poeticus/issues/339)；**8B 的文学提炼与 Refine 质量尚无实测**，应先执行 [#341](https://github.com/montricwang/poeticus/issues/341) 的固定文献单轮对照，再决定是否扩大到自主阅读 [#312](https://github.com/montricwang/poeticus/issues/312)。下文保留 10-17 的原始研究思路，其“尽早开展自主研究”等表述不是现行交付顺序。

## 2026-10-21：观点修订原型的保存情况

[PR #348](https://github.com/montricwang/poeticus/pull/348) 做过一个**未合并、未接入 Agent** 的 SQLite 独立实验，原 PR 的变更记录仍可回查，主分支没有这套记忆实现：

- 观点经历「提出 → 质疑 → 修订 → 审阅通过／撤回」时，**追加事件而不覆盖旧内容**；可以回看修订史并按事件重建当前观点。
- 只默认召回已审阅的观点；重新修订会使旧审阅失效，撤回后不再召回。定期整理目前只是**从记录生成可回查的摘要草稿**，没有真正用模型完成语义巩固。
- 原型要求来源锚点与审阅标签，但只检查格式，**不能核实原文、真人身份或授权**；SQLite 限制改写也不是安全审计系统。
- Hindsight、LangMem、A-MEM、MemOS、PersMem 只提供思路参考，没有同时引入五套记忆框架。

**尚未完成**：拿真实文献和相反解释验证错误是否会复活、观点修订是否提高回答质量、摘要是否失真，也没有服务端权限、长期部署或自动晋升。后续由 [#347](https://github.com/montricwang/poeticus/issues/347) 验证；读者私人记忆另归 [#45](https://github.com/montricwang/poeticus/issues/45)。

## 目标与核心假设
不修改底层模型权重，让文学批评 Agent 在离线研究中自主选题、阅读、提出假说、寻找反例、维护长期记忆；检验这些经验是否提升其在未见作品上的解释能力与判断质量。不是意识或模型参数自我进化的宣称。

## 与原有四层结构的关系
- **Persona / Constitution**：保留最小、稳定的证据纪律、独立判断和诚实表达原则；不预设偏爱哪位词人或流派。原则的修改需版本管理和评测。
- **Skills**：提供细读、互文、文献考证、比较、质疑等可调用方法；允许 Agent 自主选择，未来可实验性提出新的 Skill，但须测试后启用。
- **Library**：原典、词话、论文及互联网来源，保存出处、版本和可靠性；自主决定何时检索什么，不取消 RAG。
- **Critic Notebook**：保存有依据的观点、审美倾向、反例、修订史、未解决问题；候选与正式记忆分层，不能无限追加或把自己的旧输出当外部证据。

原 #148 的四层结构是初始支架，不是需要拆除的障碍；需要逐渐减少的是人工硬编码的研究路线。

## 双循环
- **在线对话**：面向用户，按需调用 Library / Notebook，保留用户记忆与 Critic Memory 隔离。
- **离线研究**：自主选题 → 选择材料 → 阅读与检索 → 提出假说 → 证据与反例 → 反思 → 候选札记 / 研究问题 → 独立检验 → 晋升或保留争议。
两者共享 Critic Notebook，但离线任务不能未经检验修改在线使用的正式记忆。可用相同基础模型和不同角色/任务配置，无需提前堆叠多个 Agent。

## 自主性边界
人工不筛选应当喜欢苏轼还是姜夔；只限定预算、权限、材料来源、证据标准、停止条件与回归评测。模型可自主决定阅读顺序、研究问题、保留哪些候选观点；「自圆其说」不是充分证据，须寻找反例、区分价值判断与可核验事实。文学评价可多标准并存，不强求单一排名。
「前人未研究」必须先做文献查新，不能以模型没见过为依据。允许无新见解、保留疑问或撤回问题。

## Bootstrap v0 实验
选苏轼、姜夔、吴文英及不同立场的原典、词话、论文；DeepSeek 推理模式优先用于自主提问、假说检验和记忆整理，常规阅读检索可用普通模式。先设小额成本上限（例如几十元，实际 token 预算待测），在独立脚本/隔离数据库运行，暂不接入线上写入。
基线：不带 Notebook 的同模型；对照：仅增加相同文献的 RAG；实验组：自主研究 + Notebook。固定未见作品测试集、不同 framing、隐藏作者、跨作品一致性与引用真实性；评估问题新颖性/价值、解释具体程度、反例处理和校准，不只看模型自评。保留运行日志、成本和研究轨迹。不能把新颖的表达直接当作新知识。

## 后续阶段
1. Critic Bootstrap：自主阅读与初始 Notebook。
2. Autonomous Research Loop：自主选题、Research Questions、周期性研究。
3. Critic Evaluation：独立评测、候选晋升、回归测试。
4. 产品候选：「Poeticus 正在思考」展示经核查的开放问题，允许读者提供线索但不直接改写公共审美记忆。

## 明确非目标
当前不做 RL / LoRA / 权重更新；不以蒸馏名义宣称完成模型训练；不默认 AI 的自评分数高于人类或独立证据；不将研究假说当作已实现能力；不打断当前首页开发。

## 2026-10-17 补充：启动时机、文风、诊断与模型实验

### 分层推进，不等待 RAG 完工
1. **现在：Critic Style Skill**。先调整 DeepSeek 的对答文风：减少古板、空泛升华、机械分条、套话；不是简单禁词清单。用真实文学问答做小样本回归，文风与事实正确性分开评价，不需微调。
2. **并行：最小研究工具链**。复用现有诗歌 RAG，逐步补充原典定位、词话/论文检索、出处与版本核对、反例检索。按真实研究阻塞补能力，不等“完整文学 RAG”建成。
3. **尽早：小规模自主研究**。先在隔离环境里研究少量可靠文献与问题，保留完整研究历史和候选 Notebook；不急于大规模烧 token，不直接写入线上正式记忆。
4. **随后：独立评测、扩大循环**。有可用证据核验、trace 和基础问答基线后，再增加轮次和预算。

### 风格、研究能力、品位分离
- **表达风格**是产品体验，可以尽早稳定并版本化；Style Skill 不应暗中规定文学立场。
- **研究能力**来自工具、证据纪律和实践，可以与 RAG 共同演进。
- **审美品位**来自长期判断、反例与修订，不人为规定何时“形成”，也不以观点稳定替代正确性或论证质量。Persona 稳定的是研究原则，不是偏好结论。

### 防止只研究艰深问题
- 建立**基础能力诊断集**：普通用户常问的字词、典故、词牌与词题、作者背景、作品解释、文学史、赏析等。AI 可生成数百道候选题，但需抽样核验并保留独立测试题；不是强制学习顺序或预写标准答案库。
- 研究动机双轨：**自主好奇心驱动** + **诊断/真实用户问题暴露的能力缺口驱动**。Agent 自主选择如何补课，用户偏好不直接写入 Critic Persona。
- 同时测量普通问答覆盖率与深入研究质量，避免“高屋建瓴却不懂基础”。

### 模型无关的 Research Harness 与 Trace
- 暂不押注 Claude / GPT / DeepSeek；比较**同等预算**（强模型少轮次 vs 低成本模型多轮次）及**同等研究轮数**两种实验，统一资料、工具、初始 Notebook、目标和评测，允许自主选题。
- 每轮记录：研究问题、选择资料与出处、工具调用、假说、反例/修订、Notebook 差异，以及 token、费用、耗时、失败与停止原因。
- 工程 trace 可用 LangGraph / LangSmith；另生成便于人读的研究时间线。记录可观察行为及模型主动给出的决策说明，**不宣称能够读取模型全部内部推理**，不强迫冗长思维报告。
- 比较有效研究成果、基础能力改善、引用准确性、反例处理和成本；不把长篇札记数量当成果。

### 首轮执行约束
以小额硬预算启动，先做最小闭环：**一个自主问题 → 检索与核验 → 假说/反例 → 候选札记 → 可回放 trace → 独立评测**。首轮不追求百篇文献或数百轮研究；预算、具体模型与样本数以实际 API 可用性和成本实测决定。此节是方案，尚未实施。

## 已有文学批评方法材料与 Skills 晋升条件（2026-10-20）

[《唐宋词鉴赏辞典》首轮批评方法提炼 #354](https://github.com/montricwang/poeticus/issues/354) 已完成**模型阅读与结构化归档**，不是文学判断能力验收。PR #373 的可公开事实是：从 1505 篇可分篇赏析形成同数的私人 `records/`、`cards/`，以及可再生成的 JSONL；其中前 20 篇 `pilot_v1` 与后 1485 篇 `article_v2` 并存。得到 7927 条方法观察、23898 条引文索引；另有 7 个原 EPUB 分篇异常需要单独调查。实际现代赏析正文、研究卡和引文索引**存放在私人工作区，不发布进 Git**。

使用这些材料必须分开四层：

- **引用/出处**：一个字符串能在所给 EPUB 段落中找到，只说明定位正确，不保证研究者的文学解释为真。
- **观察/主张**：记录评论者从哪些词句、对照材料、历史证据提出了什么判断；保留作者的推测及其局限，不将评论家的现代心理解释写成古人本意。
- **可迁移方法**：例如替换关键词观察效果、倒读结句、比较唱和作品的差异、寻找反例和回应旧说。先抽出具体论证动作及适用条件，不直接移植评论者立场或文风。
- **Skills 候选与正式使用**：必须在未见作品上与「无额外方法卡」和「只增加同量文献证据」进行受控对照，核对引文真实性、反例处理与自然度；没有稳定收益就只保存研究索引。

当前审核、归纳和迁移验证集中在 [#372](https://github.com/montricwang/poeticus/issues/372)，不能因为 1505 条目生成完成，就把它们全部注入 Prompt、RAG 或 Critic Notebook。Persona 稳定研究纪律；Notebook 留可修订的个人观点；Library 保存原典，Skills 只接收经过实践验证的**做法**。另见 [#148](https://github.com/montricwang/poeticus/issues/148) 的四层设计。
