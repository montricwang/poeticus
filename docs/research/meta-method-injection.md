# 元方法注入：让 Critic 解释、检验并修订研究策略

> 状态：架构研究草案（2026-10-23），**不代表已实现或已选型**。主议题 [#407](https://github.com/montricwang/poeticus/issues/407)，后续元认知文献调研 [#408](https://github.com/montricwang/poeticus/issues/408)。
>
> 目标不是强制模型输出更长的“思维过程”，而是让 Poeticus 产生**有证据、可观察、可评价、可复核的研究决策**，并在后续研究中利用验证过的方法经验。

## 1. 为什么现有结构还不够

当前的 `backend/ai/graph.py` 已有 `AgentState`、`loaded_skills`、`tool_calls`、`tool_results`、`evidences` 和 ReAct 的 `agent → tools → agent` 循环。它能表示“做了什么”，但没有独立的对象回答“为什么采用这条研究路径、准备怎样证伪、什么情况需要换方法、结果如何反馈给下次研究”。

现有 [14 类批评方法](./critic-methods-overview-2026-10-21.md)侧重“怎样分析”；王兆鹏《词学研究方法十讲》的六种支持型工作流候选主要回答“如何查证、如何组织证据”，原始研究资产保存在私有目录 `poeticus-data/reports/ci-methods-ten-lectures-2026-10-22/`；张伯伟《中国古代文学批评方法研究》的三种内在批评方法、六种批评表达形式，可以成为批评视角与表达策略的候选来源。三者尚未构成一个自动选择、修订研究策略的生产系统。

### 能力层次（是职责划分，不是必须逐层执行的模型流水线）

| 能力 | 回答的问题 | 目前主要承载 |
| --- | --- | --- |
| 材料与证据（RAG / Library） | 有哪些可靠材料？ | Corpus、Retrieval、Evidence |
| 具体方法（Skill） | 怎样分析、怎样查证？ | 14 类 Skill、六种工作流候选 |
| 工作组织（ReAct / Plan） | 这一题接下来做什么？ | 当前 ReAct；显式 Planner 尚待验证 |
| **元方法（Meta-method）** | 问题是否问对？为什么选这个方法？如何发现选错并修订？ | 待设计的策略选择与复盘机制 |
| 经验积累（Method Learning） | 哪种选择在何种条件下经过验证、值得复用？ | 候选方法库与验证记录；尚未接入 |

“方法路由”只是元方法的一部分；重新界定问题、选择比较维度、判断研究充分性、处理反例和停止调查同样重要。真实研究会在这些层次之间往返，不必强制每题调用 Planner。

## 2. 三种对象及主权

| 对象 | 含义 | 最小有效信息 | 不应该混入 |
| --- | --- | --- | --- |
| **Method** | 可复用的研究操作或判断准则 | 来源、适用条件、限制、预期证据、验证状态、版本 | 某位作者的结论作为普遍真理 |
| **Research Strategy** | 当前任务为何选用/组合这些方法 | 研究问题、可检验假设、选择与备选、证据要求、复审条件 | 模型“脑内思维链”的声称 |
| **Research Trace** | 任务实际执行产生的可见事件和修订 | 时间顺序、工具调用、实际材料、方法调整、错误、结论、人工评价 | 未经证实的模型自我评分 |

补充两种已有责任：**Literary Notebook** 保存文学观点及其证据、争议和修订史；**Method Notebook / 候选经验** 保存研究策略的适用性发现，须经核验后才能进入正式 Method。用户的私人 **Mem0** 仍只负责私人偏好和用户控制的数据，不自动并入 Critic 的共享经验。

策略应当是本次任务可修订的实例；正式方法以可审查、可回滚的版本为准；运行轨迹为事实记录，不能让模型改写过去发生的工具事件。

## 3. 元方法怎样“注入”

优先尝试**按任务需要提供简短策略准则与方法元数据**，不预先新增一个 Meta-Agent。

1. **任务判断**：确认用户要解释、考证、比较或持续研究，是否真的需要计划。即时事实/释义可继续普通 ReAct。
2. **方法发现**：根据任务查询候选方法的描述、适用与失败条件，再由模型选择。不得仅按关键词固定映射一个方法。
3. **策略外化**：仅对值得规划的任务产生可见或可存的简短结构：当前问题/假设、选中方法与备选、将寻找的证据、何时复审。
4. **执行与观察**：沿用已有工具池与具体 Skill；工具事件、真实来源和遇到的冲突由系统记录。执行器内可以继续使用 ReAct。
5. **有限复审**：证据冲突、资料缺口、方法不适用或研究范围发生变化时，允许修订计划；必须注明**可观察的触发事实**。不强制无限循环。
6. **研究落盘与候选学习**：文学结论进入 Notebook 候选；策略成败进入 Method Notebook 候选；只有跨案例复核后，才能修改正式方法库。

### 一次任务的示例（不是固定 Schema）

> 问题：姜夔的“清空”主要源于个人遭际，还是艺术传统？

- 研究问题重构：原题的二选一是否成立？是否还有词体审美、接受史等解释？
- 候选视角：以意逆志、推源溯流、作品内部审美分析；不是三条必须全走的管线。
- 需要查证：可靠的生平/系年材料、相似或相反的作品实例、早期词论中的概念用法。
- 备选路径：如果传记材料不能支持心理因果，就弱化作者意图推断，转向可比的文本证据。
- 可检验的策略修订：记录“哪个来源或反例触发了改变”，同时保留未解问题。
- 输出：区分已核事实、竞争解释、审美判断及确定程度；保存真实来源，不以优雅说辞代替证据。

## 4. 关键认识论界限：外显理由不等于内部思维

模型可能在向量计算中形成复杂的内部表示。提示模型“逐层吐出思考”，**只能得到模型生成的可见文本或结构化报告**；它不能证明这些就是导致回答的内部因果过程，报告也可能事后合理化。不能把“模型解释了策略”直接当成“我们读懂了模型的元认知”。

因此优先要求**行动前的可测试承诺**（研究目标、证据预期、停止条件）和**行动后的事实对照**（具体查到什么、是否遵守承诺、为什么修订）。研究轨迹中的工具执行和来源锚点由程序记录。人工的元认知能力体现在：识别问题框定是否合理、找反例、检查因果归因，并决定哪些策略值得保留。

这也为 [#408](https://github.com/montricwang/poeticus/issues/408) 留出范围：研究元认知监控、策略控制、错误校准和反思性判断的认知科学框架，先验证可迁移的**外显行为**，不把人类认知理论直接等同于 LLM 内部机制。

## 5. 最小实验与升级条件

先不建表、不改生产 Agent。选三类陌生问题：**整首赏析、文献考证、跨作品比较**；覆盖题面错误前提、遇反证需换策略、不需要规划的简单题。

同模型、同资料、同工具预算比较：

- A：现有 ReAct；
- B：提供一套固定方法或计划；
- C：提供候选元方法与简短决策记录，允许受限的一次策略复审。

检查**结论准确性、引文可回查性、关键反证覆盖、问题重构质量、策略修订是否由证据触发、延迟与 Token/工具成本**。不能用“解释更长”“模型自评更高”证明元方法有效。采用未参与提炼的案例，保留失败题；先做少量盲核，不声称统计显著。

如果 C 没有可靠的净增益，停留在研究草稿；如果确有收益，再决定是否增加 Method Registry、Research Strategy/Trace 的持久化、LangGraph Planner 或多 Agent 分工。未满足独立上下文、并行或专业能力收益之前，不预设 Multi-Agent。
