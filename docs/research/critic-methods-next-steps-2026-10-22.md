# 14 类批评方法首轮产物审查与下一步计划

状态：十四类候选 Skill 已齐，暂停大规模批量提炼，转入质量盘点、边界整理与小规模验证。尚未完成全面文学判断核验，也未接入生产 Agent。

## 当前结果

《唐宋词鉴赏辞典》1505 篇研究共整理出 7,927 条方法记录、14 个方法大类。私人研究目录中，14 类均有来源记录、首轮编码、分类文件，以及简洁版／标准版／详细版候选，共 42 份。

结构检查确认：各类来源记录与编码记录的 ID 和顺序对应；共 7,927 条来源记录、7,927 条编码记录，未发现跨类重复 ID。这证明文件与记录对应完整，不代表方法归纳、引文或文学判断均已核实。

## 现有质量问题清单

### 1. 记录结构与状态不统一

- INTERTEXT 的既有 225 条记录与后续 724 条记录使用不同字段结构。
- NARRATIVE 与 STRUCTURE 各有两种记录结构。
- 各类复核状态的定义与标注方式不完全一致，当前计数不能直接横向比较。
- 需要统一的是可共享字段与状态映射；允许保留类别专属字段，不强行把不同方法压成同一模板。

### 2. 已知引文定位异常

- TEXT_WORD：41 处锚点尚未通过段落哈希和字符位置核验，涉及 20 条记录。
- HISTORY：29 处未解决锚点，涉及 13 条记录。
- PROSODY：8 处未解决锚点。
- IMAGE：10 处锚点不匹配，涉及 4 条记录；引文文字可在指定 EPUB 中找到，但坐标／哈希尚未完全吻合。
- STRUCTURE：44 处严格锚点尚未通过，涉及 19 条记录；已找到短引不等于段落哈希和字符偏移均通过。
- NARRATIVE：另有 11 处证据定位尚未核实。

应先逐项处理这些已知异常，不用随机抽样代替对已知问题的核查。每项记录修复并复核、保留为未解决，或确认原检查口径有误；不能只改状态而不留下依据。

### 3. 方法归纳仍待核验

- 标为“尚待核验”：TEXT_WORD 641 条、HISTORY 79 条、PROSODY 32 条。
- 标为“存在争议”：DEBATE 203 条、ALLEGORY 73 条、COUNTERFACTUAL 51 条、STRUCTURE 181 条。
- 其他待核记录：NARRATIVE 57 条、ALLUSION 24 条、AESTHETICS 11 条。
- TIME_SPACE 的 401 条记录均注明尚未独立核读原赏析段落；ALLUSION 尚未完成独立原始来源核验；IMAGE 有 91 条案例的原赏析仍待进一步复核。
- CONTEXT 已对 110 条做过结构化二次分析，TIME_SPACE 已重新考虑 42 条记录；这不等于全类逐篇核验。

- **审计材料覆盖不均**：HISTORY、INTERTEXT、PROSODY、TEXT_WORD 有 `citation-audit.json`；NARRATIVE、STRUCTURE 有证据定位审计；CONTEXT、IMAGE、TIME_SPACE 有 validation report；AESTHETICS、ALLEGORY、ALLUSION、COUNTERFACTUAL、DEBATE 当前未发现同口径的专门引文/验证报告。各报告检查范围不同，不能把“结构校验通过”视为“原赏析和方法归纳已通过”。

上述状态不代表相关记录必然错误。必须区分“结构有效”“引文定位通过”“方法归纳可信”与“文学解释成立”。

### 4. 十四类之间可能存在重叠

目前应审查、但不能预先判定为错误的边界包括：

- TEXT_WORD 与 PROSODY：字词选择、句法和声律有时共同解释同一现象。
- ALLUSION 与 INTERTEXT：典源辨识和跨文本关系相关，但不完全等同。
- CONTEXT 与 HISTORY：作品语境、历史事实和史料核验的职责需要划清。
- STRUCTURE、NARRATIVE 与 TIME_SPACE：篇章关系、叙述顺序和时空转换可能交叉。
- IMAGE 与 AESTHETICS：具体感官／意象组织与整体审美效果可能构成不同层级。
- COUNTERFACTUAL 与 DEBATE：替代写法比较与争议论证检验可能共享部分步骤。

处理方式：先比较职责、适用条件、子方法和代表记录，形成跨类对照表及建议；不自动合并类别，不以标签互斥作为目标。

### 5. Skill 版本与运行时组织尚未设计完成

- 简洁版、标准版、详细版是同一分类的候选表达层级，不应被当成 42 个互相独立的 Skill。
- 需要比较各版本的重复规则、独有步骤、适用条件、失败边界和上下文成本，决定是否采用“简短入口 + 按需加载详细参考”的组织方式。
- 当前生产代码的 `prompt_loader.py` 只注册固定 Prompt，没有动态 Skill 注册或加载；Agent 将固定提示词与 `tool_choice="auto"` 交给模型。候选 Skill 尚未接入生产运行时。
- 当前代码中的工具调用预算为 2；预算配置仍由 [#390](https://github.com/montricwang/poeticus/issues/390) 跟踪。

### 6. 工具路由与工具覆盖尚未经过对照验证

不能仅凭某个问题没有调用工具，就认定缺少工具。需要区分：

1. 模型没有识别出需要外证；
2. Skill 没有给出合适的触发条件或步骤；
3. 适用工具没有在本轮开放；
4. 工具存在但查询参数不合适、检索失败或结果不足；
5. 已获得材料，但模型没有正确解释或引用。

版本对齐／异文比较、人物与作品时间线、本地古汉语词典查询、引文定位校验等是候选能力缺口，尚未证明必须新增工具。先审查现有能力和失败轨迹，再决定开发。

## 推进顺序

### 1. 完成质量问题盘点与分级

把结构、引文、方法归纳、分类边界、Skill 版本组织、工具路由和评测缺口放在同一清单中。每项注明证据、影响范围、当前状态和下一步；区分已确认问题与待验证假设。当前文件作为汇总入口，原始赏析和研究卡继续留在私人数据目录。

### 2. 处理确定性的数据与证据问题

- 先处理已知引文锚点异常，并记录每项的复核结果。
- 再定义共同字段与状态映射，保留原始 source/coding 文件，生成独立规范化导出。
- 验收：7,927 条记录可解析，ID、顺序、来源关系不变；未映射字段、状态及未解决锚点均有清单。

### 3. 整理分类边界与 Skill 组织方式

- 形成十四类职责、适用问题、主要分析动作、相邻类别和边界案例的对照表。
- 比较简洁版／标准版／详细版，提出统一的 Skill 目录与按需加载方案。
- 验收：主要重叠有明确处理建议；每类职责清楚；未决项保留理由和来源 ID；不因追求分类整齐而强行合并。

### 4. 审查 Skill 对工具选择的影响及潜在工具缺口

先基于现有代码和工具定义绘制“问题类型 → Skill 触发条件 → 可用工具 → 预期证据 → 失败归因”关系。此阶段只做分析和离线实验设计，不修改生产 Agent，也不先开发猜测中的新工具。

### 5. 做 6–10 个问题的小规模对照试验

比较不加载 Skill、单独加载相关 Skill、按需组合多个 Skill。固定模型、问题、可用材料、工具权限与调用预算；记录完整工具轨迹，重点观察是否漏查、错选、重复调用、参数不当、结果误读，以及多个 Skill 是否互补或造成重复和僵化。

把工具未提供证据与模型拿到证据后误读分开统计。小样本只用于发现明显问题，不宣称统计显著，也不以实验示例替代独立测试题。

### 6. 决定每类 Skill 的下一步状态

根据质量盘点、边界审查、证据复核与小规模试用，将每类标记为“可继续试用”“需要修改”“证据不足”或“暂缓”，并记录理由。更大规模题库与整体能力评测衔接 [#311](https://github.com/montricwang/poeticus/issues/311)／[#314](https://github.com/montricwang/poeticus/issues/314)。

## #372 的收口条件

- 质量问题有统一清单、证据与优先级。
- 规范化导出可追溯，已知引文异常都有明确处置状态。
- 有十四类边界对照表与 Skill 版本组织建议。
- 有可回查的小规模试验、工具轨迹和失败归因。
- 每类候选 Skill 有明确状态和后续建议。

本阶段不修改生产 Agent，不把生成 Skill 等同于能力提升，也不以小规模试用宣称整套 Critic 已得到验证。
