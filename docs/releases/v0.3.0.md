# Poeticus v0.3.0

v0.3.0 把 Poeticus 的 AI 伴读推进到真实的前代文本检索。读者现在可以直接追问“一句词可能借了谁哪一句”，Agent 会调用 Poeticus 自建 Text Retrieval Service，从约 85 万首古典诗词中寻找候选，再结合原文给出判断。

这一版也收录了 v0.2.0 之后的移动端 / 平板阅读调整、Seed AI Eval、Retrieval Eval 和生产部署整理。

**在线体验：** https://poeticus-web-production.up.railway.app/

## 前代文本检索

v0.3.0 新增完整的 Hybrid Text Retrieval 链：

```text
用户问题
→ Agent Tool routing
→ deterministic Query Plan
→ Qwen sentence / clause Dense Retrieval
→ character 2-3 gram BM25
→ Work-level RRF
→ chronology Candidate Eligibility
→ Top-K candidates
→ Agent 判断
```

当前 Retrieval Corpus 来自 Werneror/Poetry：

- 853,385 Works；
- 4,822,054 sentence chunks；
- 9,425,173 clause chunks。

Dense Retrieval 使用 Qwen3-Embedding-0.6B。Lexical Retrieval 使用 character 2-3 gram + SQLite FTS5 BM25。sentence 与 clause 两种粒度都由真实 Case 证明有独立增量，因此同时保留。

对应主线包括 #125、#128、#132、#134、#135、#136、#137、#138、#139、#140、#141、#142、#143、#144、#146、#159、#161、#162、#165。

## Agent 已经能使用 Retrieval 证据

用户明确追问：

- “这句借了谁哪一句？”
- “这里可能化用了什么前代文本？”
- “和哪一句前代作品最值得比较？”

Agent 会优先使用 `search_predecessor_texts`。

如果第一轮候选较弱，Agent 可以在当前工具预算内换一个更有辨识度的文本锚点继续检索。

线上已经完成陆游 canary：

```text
片片轻鸥落晚沙
→
杜甫《小寒食舟中作》
娟娟戏蝶过闲幔，片片轻鸥下急湍。
```

最终回答同时保留文学判断的边界：文本对应可以很强，仍需区分“高度可能的化用”与“有明确文献记载的引用”。

## 独立 Retrieval Serving

Retrieval 目前单独运行在腾讯云上海 2C8G Linux 节点：

```text
Railway Web / Agent
        │
        │ HTTPS + Bearer token
        ▼
Tencent Cloud Nginx
        │ localhost
        ▼
Text Retrieval Service
```

当前 Serving Bundle：

| Artifact | 大小 |
| --- | ---: |
| sentence FAISS | 1.189 GiB |
| clause FAISS | 2.320 GiB |
| sentence BM25 | 1.557 GiB |
| metadata v2 SQLite | 1.828 GiB |
| Qwen model | 1.125 GiB |
| 合计 | 约 8.02 GiB |

原始 sentence + clause float16 Embedding 约 27.17 GiB，继续保留为离线构建资产。

FAISS 使用 IVFPQ：

```text
nlist=512
pq_m=256
pq_bits=8
nprobe=64
```

2C8G Linux 实测：

- ready RSS 约 4.4 GiB；
- benchmark 后约 5.3 GiB；
- 首次 cold start 约 34.9 s；
- page cache 后一次真实 restart 约 18.25 s；
- 5 并发约 1.78 req/s；
- 没有持续 swap 或 OOM。

这组数据也结束了第一轮服务器规格猜测：现阶段 8 GiB RAM 可以承载 full Corpus single worker，后续先观察 CPU / concurrency。

## HTTPS、认证与运维

Retrieval 进程：

- systemd 管理；
- 只监听 `127.0.0.1:8787`；
- Nginx 提供公网 HTTPS；
- Security Group 不开放 8787；
- Railway 使用 Bearer token；
- token 保存在 root-only environment file。

一次真实 restart 还暴露了 readiness 边界：

```text
systemd active
→ port listen
→ local /health 200
→ public /health 200
```

模型和 Index 尚未加载完成时，systemd 可以已经显示 active，Nginx 此时可能暂时返回 502。仓库新增 Retrieval VPS deploy helper，后续部署循环等待 `/health`，不再依赖固定 sleep。

## Chronology 的处理

公开阅读数据库目前没有可靠的逐首 dynasty 字段。

当 Agent 请求里 `dynasty=null` 时，Retrieval Service 会：

1. 优先查当前作品在 Werneror 中的 exact-content alias；
2. 再看 exact author 的 dynasty 分布；
3. 只有唯一最高计数时才采用该 corpus-compatible label；
4. 模糊情况继续保留 unknown。

生产节点实际 probe：

```text
温庭筠 → 唐
韦庄   → 唐
冯延巳 → 唐
李璟   → 唐
李煜   → 唐
```

这说明 Werneror 的 dynasty 是粗粒度检索标签。南唐人物也可能归到“唐”，因此 Poeticus 不把这个值展示成精确历史断代。

## AI Eval

v0.3.0 建立了两层新的评测基础：

- Seed AI Eval：检查回答、工具调用、典故 / reference 等基本行为；
- Retrieval Increment Eval：比较独立 LLM 与工具增强后的真实增量。

当前已经能区分：

- 模型本身已经知道的经典互文；
- Retrieval 真正带来增量的长尾 Case；
- 第一轮 miss 后 query reformulation 找回目标的 Agent loop；
- Candidate 可见与文学关系成立之间的差别。

相关合并包括 #114、#116、#117、#118、#121、#143、#144。

## 当前已知边界

- #151：同一作品异本 / 重复记录可能形成 self-hit；
- Werneror dynasty 只能提供 coarse chronology；
- 同朝与 overlapping candidate 会继续保留给 Agent；
- 2C8G 的长期并发上限还需要真实流量；
- #167：Let’s Encrypt 公网 IP 证书第一次自动续期仍需运维验证；
- #163：唐宋 Serving Profile / Corpus pruning 已记录，当前 deferred；
- 3491 首公开阅读词作仍保留 `imported_unreviewed` 状态。

## 发布范围

- v0.3.0 Release 标签固定对应本次发布代码；
