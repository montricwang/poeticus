# Poeticus v0.8.0 — 文学批评 Skill 与阅读体验更新

v0.8.0 为 Poeticus 引入十四类文学批评方法的按需调用能力，并完善 Agent 工具预算与对话阅读体验。方法仍处于公开试用与持续评测阶段，不代表其文学分析质量已得到全面验证。

## 文学分析与 Agent

- **十四类文学批评 Skill**：新增从字词、意象、章法、互文、典故、声律，到史实核证、审美评价与异说比较等十四类方法。System Prompt 保留简短目录，模型可按问题需要自主读取一至三类方法正文；直接释义与简单问答不必加载。Skill 为分析步骤，不是典籍原文或史料证据。
- **加载与预算**：同一请求避免重复加载；首次有效本地 Skill 读取不占外部证据工具预算，错误及重复调用受限制。工具调用上限可使用 `POETICUS_AGENT_MAX_TOOL_CALLS` 调整为 **1–10**，默认仍为 **2**；Reader 100 评测也支持 `--max-tool-calls`，并检查续跑配置一致性。
- **研究边界**：十四类方法整理完成阶段性组织与边界说明；十题、六题小样本对照发现模型调用行为有变化，但不证明方法能稳定提高文学判断。对于「胡马窥江」等过度推断的 Bad Cases，保留回归并继续按照 #311／#314 评测。

## 阅读与对话体验

- **重新生成回答**：在原回答位置呈现新内容，不再另开临时回答框；移除重复生成提示，保留失败后的恢复路径。
- **流式回答**：新增按字符淡入呈现，调整 Markdown 节点处理和消息区高度稳定性。持续优化显示节奏与不同输出路径；相关交互任务 #37 尚未全部结束。

## 质量与工程维护

- 为 `/api/analyze` 增加输入不合法及上游异常的回归测试，避免向用户暴露上游错误细节。
- 补充文学方法的职责边界、Skill 设计原则、研究试验记录及 10 月 21—22 日 DevLog。
- 合并前全量 Python 测试 **720 passed，3 subtests passed**；前端构建、格式检查、lint 通过（lint 0 errors，存在既有警告）。自动化测试通过不等于真实浏览器、文学质量或生产环境的完整验收。
