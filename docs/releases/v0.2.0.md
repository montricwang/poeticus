# Poeticus v0.2.0

**这一版主要不是增加新的内容规模，而是把 Poeticus 从“能公开运行”继续推进到“更适合长期维护与阅读”。**

v0.1.0 解决了公网可用、3491 首宋词、AI 伴读与基本安全边界；v0.2.0 重点整理工程结构，并建立新的中文字体与诗词排版基线。

**在线体验：** https://poeticus-web-production.up.railway.app/

## 这一版完成了什么

### 工程结构整理

- 拆分前端 App 中的 UI、聊天会话、持久化与数据加载职责，降低单一入口文件的复杂度。
- 将 Python API 与 AI 代码统一归入 `backend/`，明确后端边界。
- 整理 EPUB 导入工具与重建生命周期，降低一次性脚本继续侵入生产代码的风险。
- 将运行时参数与客户端能力限制集中管理，减少前后端重复常量和配置漂移。
- 移除旧版根目录兼容层与其他历史遗留入口，并统一一批中文代码注释。

对应合并：#91、#92、#93、#94、#95、#96。

### 字体与阅读排版基线

- 建立中文宋体 / 黑体双字体体系：
  - 拉丁 UI：Inter Variable
  - 苹果中文 UI：PingFang SC
  - 其他平台中文 UI：自托管 Noto Sans SC Variable
  - 文学正文：Noto Serif SC Variable
  - 生僻字补充：HanaMin
- 明确视觉原则：**诗歌是“出版物”，界面是“软件”**；宋体负责作品阅读，黑体负责软件操作。
- 收紧词牌、小序、作者与正文之间的排版节奏。
- 阅读器排版参数集中到 `.poem-reader` 变量区，后续调优不再散落修改。
- 修复局域网 HTTP 环境下会话 ID 生成兼容问题。

对应合并：#98、#99、#100。字体比较实验 #97 在形成正式方案后关闭，未合并。

## 与 v0.1.0 相比

v0.1.0 的重点是“第一次公开可用”；v0.2.0 的重点是：

> **把工程骨架收干净，并把阅读界面的视觉语言固定下来。**

这一版没有把正在开发的移动端 / 平板响应式重构算进正式发布；相关工作仍在 Draft PR #103 中继续。

## 已知问题与下一阶段

当前已经明确但尚未在 v0.2.0 解决的事项：

- 移动端、iPad 与桌面双栏的响应式阅读 / 讨论布局仍在 #103 中继续真机验收。
- 顶部工具栏的信息层级仍需重整：主题选择、对话 / 赏析切换、生成整首赏析不应继续并列挤在一行。
- 目录与搜索需要做到一步可达，同时避免长期占用阅读宽度。
- 编辑用户问题的“书页札记”视觉、移动端渐隐层强度、桌面讨论区高度仍待视觉验收。
- iPhone 目录分页、横向溢出与选区更新问题仍需真机验证（#85、#86）。
- 上下阕间距目前仍受正文空行与行高绑定影响；未来应把诗行行距和阕间距拆成独立参数。
- “一句一行”以及多 DOM 节点下的选区坐标映射属于下一阶段诗文展示层问题。
- 生僻字跨字体 fallback 的一致性、EPUB 非正文结构分类、AI Eval / Evidence / RAG 仍保留为后续专题。

## 发布边界

- 本 Release 以 v0.2.0 标签对应的 `main` 为准。
- Draft PR #103 及其后续响应式改动不属于本 Release。
- 3491 首作品仍属于导入后未逐首人工校勘的公开语料；AI 解释、译文与典故检索仍可能出错。
- 匿名 AI 仍受共享额度、限速与并发保护，不是无限免费模型接口。
