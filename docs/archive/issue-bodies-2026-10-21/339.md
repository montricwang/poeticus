## 背景与目的

2026-10-19 记录 Prism ML [Ternary Bonsai 2 27B](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf) 作为一个**本地模型推理候选**。它基于 Qwen3.8-27B，采用三值压缩：PTQ1_0 权重约 5.95 GB、PQ2_0 约 7.21 GB，官方声称在其汇总基准上保留 FP16 版本 98.2% 的性能。以上是**厂商基准声明，未经 Poeticus 实测**。模型卡标注 Apache-2.0。

关注的产品需求：让 Poeticus 在不完全依赖外部大模型 API 的情况下，具备可控的离线/本地模型推理、模型替换、私有实验和未来小规模定制的选择。**评估本地推理和 LoRA 是否可行是两个不同问题**；不要因为 GGUF 权重小就推断训练显存同样小。

## 边界与本轮结论

- **推理**：5.95 GB 只是模型权重大小；实际运行另需 KV cache、运行时/计算缓冲、上下文和可能的视觉模块内存。PTQ1_0 与 PQ2_0 有不同内存/性能权衡；8GB 显卡可能仅能尝鲜，必须实测速度和内存峰值。
- **兼容性**：Bonsai 2 目前要求 PrismML 定制版 llama.cpp（Hadamard 激活变换及特殊量化格式）；普通 llama.cpp / Ollama 不可默认直接运行。官方运行入口：https://github.com/PrismML-Eng/Bonsai-demo 。
- **微调**：优先区分「在可训练的原版/标准量化基座上做 LoRA/QLoRA，然后部署/量化」与「直接对 Bonsai 2 特殊 GGUF 权重做 LoRA」；后者不能预设现有 PEFT / QLoRA 流程支持。自建预训练模型暂不考虑。
- **部署**：本地开发机跑通不意味着适合 Railway 或现有 Poem Retrieval 服务承载公网并发；核算显存、常驻成本、吞吐、冷启动、并发和运维。
- **DeepSeek**：DeepSeek 的托管 Search/Fetch API（#153/#155）与**本地推理**无关；只有获得可下载且许可允许的对应模型权重，才谈得上本地部署，不能把 API 服务当作本地权重。

## 2026-10-19｜首次本地实测：已确认什么，尚未确认什么

**实验设备**：普通 Windows 笔记本，i5-13500H、32 GB RAM、Intel Iris Xe 集成显卡；WSL 约 15 GiB RAM 配额 + 4 GiB Swap。GPU 实验使用 **Windows 原生 Vulkan**；WSL Vulkan 枚举的仅是 `llvmpipe` CPU 软件设备。为免干扰 Document RAG 和 Retrieval，模型实测在隔离环境进行，未改产品 Agent、线上模型密钥或生产路由。

所有权重从国内镜像下载并校验 SHA-256（原始路径、具体安装命令、校验指纹和日志留在**私人 Vault**，不复制机器特有信息到公开 Issue）：

| 模型 / 量化 | GGUF 文件大小 | CPU 生成 | Intel Iris Xe Vulkan 生成 | 当前验收 |
| --- | ---: | ---: | ---: | --- |
| Qwen3.5-4B Q4_K_M | 2.74 GB | 8.97 Token/s | **12.51 Token/s** | CPU/GPU 均已跑通；一次简单中文问答完整 |
| DeepSeek-R1-0528-Qwen3-8B Q4_K_M | 5.03 GB | 5.93 Token/s | **8.29 Token/s** | CPU/GPU 均已加载并生成；短 Smoke Test 的 96 Token 被 `<think>` 耗尽，**还没验证完整文学回答** |
| Ternary Bonsai 2 27B PTQ1_0 | 5.95 GB | 1.09 Token/s | **2.38 Token/s** | Prism ML 定制版 llama.cpp + Windows Vulkan 生成完整中文句子；缓慢，不适合立即承担长文反复修订 |

数据来源：**同机短 Benchmark，每个模式仅 1 次**，Qwen 的 pp64/tg64、8B 的 pp32/tg32、Bonsai 的 pp16/tg16；它们**不是同长度跨模型质量比较**，没有稳定性/统计误差保证。Qwen/DeepSeek 的 GPU 生成约比同机 CPU 快 1.4 倍；Bonsai 约 2.18 倍，但 27B 的提示词处理仍约 1.42 Token/s，长文尤其不实用。Intel 核显共享系统内存，能成功加载模型不等于资源宽裕。

**推理链路与研究能力分开看**：

1. **已证实**：4B、8B、27B 均能本地离线推理；8B 可在现有笔记本上低速使用；Windows Vulkan 可真实调用 Iris Xe，Bonsai 的极低位权重需 Prism ML Fork。
2. **没有证实**：8B 是否擅长词话提炼、跨文献观点归纳、批评或 Refine；多轮循环是否比一次生成更好；本地运行时是否可在长上下文/多并发下稳定支持 Poeticus。
3. **阶段判断**：先不因实验成功而替换云端主 Agent；也不因为 Bonsai 仅 5.95 GB 就推断其计算速度与 8B 接近。当前笔记本适合小样本离线研究，云端仍适合复杂长篇批评任务。
