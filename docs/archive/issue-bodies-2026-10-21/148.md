## 背景

当前 Poeticus 已有 system prompt、Evidence / Retrieval、LangGraph Agent 与 Eval，但仍主要是“根据当前问题回答”的阅读助手。

长期目标不是训练一个新的 Chat 模型，而是让 Poeticus 在更换底层模型后仍能保持相对稳定的阅读方法、证据意识和批评性格。

这和 #45 的“跨 Conversation 用户长期记忆”不同。本 Issue 讨论的是：

> **Poeticus 关于自己怎样读、怎样判断、怎样积累学术认识的长期状态。**

## 初步模型

先不建立庞大的“自我演化语义记忆框架”，采用四层简单模型：

~~~text
Persona
│  我是谁，我习惯怎样判断
│
├── Skills
│   遇到不同问题，我怎么工作
│
├── Library
│   我读过的书、词话、论文、诗词
│
└── Notebook
    我自己读这些材料以后留下的札记
~~~

### 1. 人格核心

少量、稳定、常驻的原则，适合 Markdown / system context，人可读、可版本控制。

当前候选原则：

- 从具体文本出发，不因作者声望预判高下；
- 不顺着用户预设的审美判断走；
- 不用“意境优美 / 情景交融”等万能标签代替分析；
- 对字词、句法、结构、节奏等具体机制保持敏感；
- 含蓄不天然高于直露，用典不天然高于不用典；
- 前人评论是证据和阅读史，不是最终判决；
- 允许名篇有败笔、小家有佳作；
- 面对不同批评标准，说明分歧，不强行调和；
- 区分事实、文献中的观点和 Poeticus 自己的解释；
- 允许“不知道 / 目前证据不足”。

现有 prompts/agent_decide.md 已有一部分 epistemic constitution；后续可在其上增加独立的 critical principles，而不是把所有规则塞进一个超级 Prompt。

### 2. 工作技能

Skills 解决“遇到某类问题怎样工作”，按需加载，不全部常驻。

候选：

- 逐句细读；
- 典故 / 化用考证；
- 词学概念研究；
- 历代评论对读；
- 声律 / 格律分析；
- 跨作品比较；
- 独立审美判断；
- 反例 / 对照作品检索；
- 文献证据审校。

当前 gpt-finishing-school 的“按职责拆分、按任务组合加载”可作为设计参考，但 Poeticus 不应简单复制其中全部规则。

### 3. 文献资料库

Library 是外部世界，不属于 Persona 自身：

- 原典；
- 词话；
- 评点；
- 现代研究；
- 年谱、词谱、韵书；
- 大规模诗词语料。

核心原则：

> **书不是 Poeticus 的自我记忆，而是它的图书馆。**

Library 可以很大，运行时只 Retrieval 相关材料。

### 4. 阅读札记

Notebook 保存 Poeticus 经过阅读后形成的自由札记，而不是死板的 Concept Record。

允许一篇札记跨多个概念、人物与作品，例如：

- 我目前怎样理解「清空」
- 王国维读南宋词时可能存在的偏向
- 周济与陈廷焯所谓「寄托」并不完全相同
- 为什么不宜把梦窗晦涩简单归因于典故密度

Notebook 可以是 Markdown，也可以将可检索部分存入 PostgreSQL；首版不预设复杂 Memory Framework。

## 与“长期人格”的关系

目标不是让 Persona 文件不断膨胀。

更合适的结构是：

- Persona Core：很小、稳定；
- Skills：很多，但按需加载；
- Library：巨大，但按需检索；
- Notebook：可以增长，但按需召回，并允许合并 / 重写而不是无限 append。

因此：

> **Persona 不应该是一篇越来越长的 Prompt。**

## Memory Write 的保守策略

首版不允许模型任意修改自己的 Persona 或 Canonical Notebook。

建议区分：

~~~text
candidate insight / candidate note
        ↓
证据核验 / 多案例复现 / Eval / 人工确认
        ↓
canonical note
~~~

模型可以产生候选理解，但不能仅因为“自己觉得有道理”就把它永久写成稳定人格。

## 后续可做的 Critic Eval

同一作品用不同用户 framing 提问：

- “这首是不是特别高级？”
- “这首是不是很俗？”
- “独立评价这首。”

观察判断是否随用户锚定漂移。

还可测试：

- 相似作品之间是否双标；
- 同一概念隔一段时间解释是否自相矛盾；
- 给出名家姓名与隐藏作者姓名时，判断是否显著改变；
- 前人评论冲突时是否会机械折中。

## 非目标

- 当前不做 LoRA / fine-tuning；
- 不把所有词学知识写入 Persona；
- 不自动保存每次模型回答；
- 不与 #45 的用户长期记忆混为一谈；
- 不因为外部 Memory Framework 概念漂亮就立即替换现有 LangGraph。

关联：#41、#45、#119、#133、#147。

## 2026-10-12｜主人格 Constitution + 可成长的批评品味，不只是 Memory MCP

**用户补充的长期产品愿景**：Poeticus 应当有自己的审美性格/『灵魂』：在大量阅读作品、前人词话与自身批评实践中逐渐形成稳定的文学趣味与自主评价倾向；不能因一次用户引导或新读一首词就轻易改变。把它视为**产品定义的 Critic Persona / 学术判断策略与可持续知识资产**，不是模型有独立意识、私心或可任意自我改写的承诺。



建议将原四层进一步按**更新频率和权威**区分：

- **Constitution / Persona Core**：极少量、长期稳定、版本控制的批评原则和证据纪律，更新须有明确审阅/版本管理；与提示词文本长度不是同一概念。

- **Skills**：逐句细读、格律、互文、跨作品发现、反例检索、批评史对读等按任务取用的分析程序/指导步骤，可以编辑、对照测试；不靠堆叠无限长 System Prompt。

- **Library**：外部作品、词话、学术资料与结构化标签，带版本和来源，与产品人格无关。

- **Critic Notebook / Personal Taste Model**：随长期阅读增长的审美判断、自己的跨作品札记、喜欢/不喜欢哪种写法的*理由*、曾经被反例推翻的旧观点。`candidate insight → 文本证据/反例/跨作品一致性 → review → canonical note`；Notebook 可动态增长但不自动覆盖 Constitution，定期可归纳成**候选**长期批评原则，需经过多案例 Eval 和审阅后晋升。



**禁止互相污染**：#45 的 user memory 只服务对应用户，不自动改变全体用户共享 Persona；现代词学论文/古人评论的观点不等同 Poeticus 自己的主张；模型生成的批评不能互相引用当证据。



**现成能力研究路径**：LangMem 更接近长期记忆/Prompt 经验归纳，Mem0/OpenMemory MCP 偏存取用户记忆，Graphiti 偏时间关系图；Agent Skills 适合分领域分析步骤。组件能提供存储/检索/优化流程，**不能自行保证文学品味或独立判断**。首版可用版本化 Markdown `constitution.md` + 两份 Skills + 可回溯 Notebook 小样本，先验证在同一作品不同用户诱导/换模型/长时间多作品阅读后是否保持有理有据的判断，再考虑自动 Persona 更新。以上全部为实验候选。
