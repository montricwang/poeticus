## 研究步骤（按最小闭环推进）
1. **质量与结构预检（先做）**：验证 JSONL 数量、篇号唯一性、源段引用与 SHA 是否仍可回查；统一读取 `pilot_v1.moves` / `article_v2.methods`，不改写原始卡。抽取跨作者、不同题型、长短篇、政治寄托/考证争议与明显模板化案例的分层样本，抽核是否真正忠实于赏析原文。7 个分篇异常另列清单。
2. **动作级归并，不能只数类别标签**：对每条观察抽取“提出什么问题 → 发现哪处词句 → 引入什么证据/比较 → 如何推理 → 有什么替代解释/失败条件”；识别重复动作、冲突、仅有空泛概括的条目。优先生成 10–20 个候选方法族，再人工归并或拆分；保留论文/鉴赏体裁与作者差异，不把各篇统一成名家风格人设。
3. **归纳有操作性的候选 Skill 卡**：写“适用场景、前提、可执行步骤、证据要求、反例、不能得出的结论、对应篇号”，例如“字词替换与异文比较”“典故原语境→新作的发话关系变化”“章法转折及时间尺度”“史料对读与假说强度校准”“反驳旧说但不把反证当正证”。每一类附几篇真实例与反例。
4. **小规模留出作品盲测**：先选训练归纳阶段未读取的作品/问题，固定模型、证据和预算，比较 A 当前 Poeticus、B 增加同量文献证据、C 再启用单个方法卡；考察引用准确、推理是否可追溯、替代解释、回答自然度、无凭据政治化等。控制作者标签影响，不以回答“像某某家”当成功。
5. **只在验证后决定接入**：如果没有稳定收益，保存研究索引，不增加 Agent 复杂度；若通过，另开/更新 #311、#148 和相关检索 Issue，再选择提示词按需加载、检索上下文或其它实施方式，**明天不直接把 1505 篇全塞进 Prompt/RAG**。
