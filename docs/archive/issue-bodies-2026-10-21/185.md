## 为什么做

我想通过 Poeticus **亲手学会 MCP**，而不只是知道它是一个协议。先弄清 Server 和 Client 怎样配合，再尝试把已有工具接进去。这个实验也可以成为求职时能够实际演示的内容。

Poeticus 已有两个典故／出处查询工具：`lookup_allusion` 和 `lookup_reference`。它们使用同一个 `EvidenceService`，**不需要重新写查询逻辑**。

## 一步一步做

- [x] **第一步：** 在本地启动一个最简单的 MCP Server，先注册一个不联网的示例工具；用客户端列出并调用它，亲眼看到结果。
- [x] **第二步：** 尝试把 `lookup_allusion` 接到 MCP，复用现有 `EvidenceService`。先用模拟数据检查正常调用和错误输入，再决定是否测试第三方接口。
- [ ] **第三步（进行中）：** 接入 `lookup_reference`，检查两个工具都能被发现和调用；整理最小测试与演示方法，Review 后再提交 PR。

**每完成一步再讨论下一步。** 学习中发现原计划不合适，就更新本 Issue，不提前扩大范围。

## 这次不做什么

- 不修改现有 Agent 的工具调用方式，不把线上 Poeticus 迁移到 MCP。
- 不开放公网 MCP 服务，不接触私人语料或密钥；第三方接口的授权、可用性未确认前只用模拟数据。
- MCP SDK 只用于本地实验，不加入生产运行依赖。

## 怎样算完成

我能亲手启动 Server、用 Client 找到并调用工具，并用自己的话解释：**工具究竟在哪里执行，MCP 比现有 Tool Calling 多解决了什么问题。**

相关代码：`backend/ai/graph.py`、`backend/evidence/service.py`。个人理解与疑问另外记在私有 Vault 的「工程学习」目录；本 Issue 只记录任务与实际验证结果。
