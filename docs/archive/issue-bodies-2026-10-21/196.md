## 背景与目标

Poeticus v0.3.0 已有 FastAPI → LangGraph ReAct → CNKGraph / 独立 Text Retrieval Service → SSE 的真实链路，并有 Seed AI Eval、Retrieval Increment Eval、LangSmith 可选 tracing 和 #77 的基础日志 / 用量保护。

目前仍缺少**针对单次 Agent Run 可独立复盘的稳定运行契约**：当用户报告「回答很慢 / 工具重复调用 / 搜索断线 / 回答引用了错误来源」时，应能在保护隐私的条件下定位失败节点、时间和降级决策。此 Issue 不以安装新 APM 平台为目标。

## 第一阶段范围：最小端到端 Run Trace

- [ ] 盘点当前 FastAPI 日志、LangGraph stream、LangSmith 和 Retrieval Service 的实际可观测字段，画出真实请求链。**复用已有能力，不重复建设平行 Trace 系统**。
- [ ] 为每次模型执行定义稳定的 `run_id` / `request_id` 及父子关联规则，贯通 HTTP → LangGraph 节点 → Tool → Retrieval HTTP Client / Server → SSE 完成或失败事件。明确多次 Tool Call、重试与 Run 的身份关系。
- [ ] 定义最小结构化事件 / span：run_start/end、agent_decision、tool_start/end、retrieval_start/end、fallback/error；记录节点/工具名、序号、status、耗时、Tool budget、错误类别及最终状态；不强制引入通用 Trace schema 或自研全新 SDK。
- [ ] 记录可获得的 usage（输入 / 输出 Token、Tool 次数、供应商用量）和端到端 latency；费用与 provider 计量**区分真实值与估算值**，缺失数据明确 unknown，避免制造准确性假象。
- [ ] 为 Evidence 保留安全的来源标识（provider / work ID / source ID）及候选 → 最终答案实际采用的关系；不能把「检索命中」自动记作「答案有依据」。
- [ ] 支持开发者根据 run_id 查看一条完整执行路径，包括成功、no_hit、超时、断连、预算耗尽、SSE 中途失败。可以优先使用现有日志/本地脚本/已有 tracing UI，不为展示而新建 Dashboard。
- [ ] 设定最小聚合视图：执行成功率、fallback 率、Tool 错误率与 p50/p95 延迟。没有足够真实流量时先展示样本与局限，不做没有意义的运营仪表盘。
- [ ] 明确数据最小化、保留期限和访问权限：默认**不记录完整私聊、作品私人注释、API Key、数据库 DSN、认证头或用户敏感信息**；使用第三方 tracing 时核实上报内容与开关。

## 具体验收

- [ ] 一条成功的有工具调用 Run：用同一 run_id 串联 API、Agent、Tool、Retrieval Service、最终 SSE，并能按节点看耗时。
- [ ] 模拟 Retrieval 拒绝连接 / 超时 / HTTP 5xx：Trace 能指出真实失败位置，区别 no_hit 与 error，并显示 Agent 是否发生受控降级；与 #180 验收衔接。
- [ ] 模拟同轮重复调用及 Tool 预算耗尽：Trace 能区分真实执行、命中复用、预算拒绝，与 #120 对齐。
- [ ] 模拟浏览器流断开：能区分客户端断流、后台 Run 是否继续、业务最终状态（若 #46 尚未实施，明确当前不可恢复的事实）。
- [ ] 通过单元 / 集成测试校验 ID 传递、事件顺序、状态语义和敏感信息脱敏；用一次真实 E2E 记录及一组失败 Trace 做人工复盘。
- [ ] 能以具体观测数据回答：一次错误慢在哪里、失败如何传播、Tool 是否带来增量、为什么没有把缺失证据写成已经核实。

## 非目标 / 停止线

不因为学习而搭建 Prometheus + Grafana + Jaeger + OpenTelemetry Collector 全家桶；不默认为每轮对话永久保存原文或 Prompt；不在此 Issue 重建 Eval 平台、Run persistence、队列或自动恢复系统。只有现有机制无法贯通跨服务 Trace 时，才选择最小必要的 instrumentation。
