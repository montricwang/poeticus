## 背景

v0.1 的对话状态采用两层轻量方案：

- 模型上下文：client-carried bounded history（#9）；
- 产品侧刷新 / 切诗恢复：浏览器 localStorage（#8）。

这足以支撑单浏览器 MVP，但 localStorage 不是长期权威存储。未来如果需要账号、跨设备、多 Conversation、服务端数据生命周期等能力，应把 Conversation persistence 迁移到后端。

## 目标

将 Conversation / Message 作为正式服务端领域对象持久化，而不是让前端长期承担权威聊天存储。

候选数据关系：

```text
User
└── Conversation / Thread
    ├── poemId / reading context
    └── Messages
```

客户端只保留必要的缓存与 Draft；服务端成为 Conversation 历史的 source of truth。

## 触发条件

出现以下真实需求之一时再实施：

- 用户登录与账号体系；
- 跨设备恢复；
- 一首诗需要多个 Conversation，并需要稳定历史列表；
- Conversation 需要服务端删除、归档、分页或生命周期管理；
- 需要分享 / 协作 / 云端备份；
- 需要 LangGraph Checkpointer 或更稳定的服务端 Thread state。

## 候选方向

- `conversation_id / thread_id`
- Conversation / Message API
- PostgreSQL 持久化
- 分页与归档
- 删除、隐私、保留期限
- optimistic update / conflict handling
- 必要时 LangGraph Checkpointer

## 不在本 Issue 范围

- Context sliding window / summary / retrieval memory；
- 跨 Conversation 长期用户记忆；
- 跨作品比较的产品交互。

长期记忆拆到独立 Issue；跨作品比较见 #43；架构演进见 #41。

## 当前决定

v0.1 不引入数据库或服务端 Thread persistence。#8 的 localStorage 只作为当前 persistence adapter，领域模型应避免被该实现锁死。

## 2026-10-12｜代码实核：Conversation 已有浏览器持久化，服务端仍缺失

基于 `main` `frontend/src/lib/chat-storage.ts`：浏览器 `localStorage` 键 `poeticus:chat-state`（schemaVersion=1）维护 `lastActivePoemId`、每首作品 `conversationId`、Turns、Draft、`updatedAt`，重载 `pending/streaming` 变为 failed/interrupted。`backend/api/chat.py` 的 `ChatRequest` 直接接收 `history`，再传给 `graph_input`；`backend/ai/graph.py` 使用 `builder.compile()`，未配置持久 Checkpointer。**因此不能说 Poeticus 完全没有 Conversation 持久化；准确说是没有服务端长期权威存储、跨设备、可独立管理多会话和 Run resume。**



用户现在希望同时支持长期用户记忆与 Poeticus 的独立批评人格记忆；后二者**不属于本 Issue 存档 Conversation 的职责**（分别 #45、#148）。未来服务端 Conversation 可以提供各自的合法输入，但创建会话记录不能自动等于创建用户总结/偏好；尤其不能把私人 Conversation 直接并入产品级人格。实际落地前另行确认账号/匿名身份、权限、数据删除、配额与迁移策略。

## 2026-10-20｜用户身份触发条件已出现，准备分阶段迁移

随着 #44 统一多场对话、#350 书房积累、#45 长期用户记忆，先前「出现账号需求再实施」的触发条件已具备。**此更新记录待施工范围，不代表服务端存档已上线**。

- 首先依 #349 选择成熟登录方案，确定可信 `user_id` / 会话；前端不再成为私有数据身份判定者。
- 保留 Conversation 稳定 ID、可选作品/阅读上下文和 Message；`localStorage` 降为缓存/草稿来源，服务端 PostgreSQL 为正式私人历史的权威存储。
- 用户首次注册时提供**明确、可取消**的本机历史导入：防止重复、串号、错误覆盖；未迁移成功时不能提前删掉本地历史。
- 会话删除与衍生用户记忆关系按 #45 的来源与删除约定执行；用户主动保存的札记/收藏按 #350 独立生命周期。
- 验收至少包含用户 A/B 数据隔离、跨设备同用户恢复、旧数据升级、删除后无法经历史 API 读回。消息分页与恢复生成 #46 可分阶段建设。
- 不必因为做了服务端对话历史便立刻引入 LangGraph 持久 Checkpointer 或复杂多租户组织模型。

关联：#349（身份与授权前置）、#44（统一对话 UX）、#350（书房）、#45（个人 Memory）。
