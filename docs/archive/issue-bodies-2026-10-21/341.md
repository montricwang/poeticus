## 背景与研究问题

2026-10-19 的本地推理实验确认：**DeepSeek-R1-0528-Qwen3-8B Q4_K_M 已能在普通开发笔记本离线加载并生成 Token**；Windows + Intel Iris Xe Vulkan 短基准约 **8.29 Token/s**（生成，单次测试）。Qwen3.5-4B Q4_K_M 约 **12.51 Token/s**；Ternary Bonsai 2 27B PTQ1_0 虽能完整生成中文，但 Intel Vulkan 约 **2.38 Token/s**，文献处理较慢。性能记录归 #339。

**关键未知是质量，不是能否加载**：8B 能否从真实词话/古典文学评论中提炼有根据的观点？经过批评再修订，是否真的比初稿好，还是越改越空泛、甚至篡改原文？

这是一次**受控的离线质量实验**，不预先决定 LangGraph、Agent 数量、Skills 或正式 Refine 工作流，也不阻塞现有 Document RAG 分支。

## 实验边界

- **输入**：少量合法、版本明确、附卷/则/段落锚点的真实文献。初版选 **3～5 段**，覆盖短而明确的评论、立场有争议的批评、概念含混或多观点的段落。先直接提供固定材料，暂不把 Retrieval 命中率混入模型质量测评。
- **任务层次**（分开评）：①提炼原文核心论点及支持依据；②区分作者原意、引述对象观点与模型推断；③对论点作有文本依据的批评或寻找反例；④根据明确反馈修订结果，并解释**改了什么、为什么改**。
- **模型对照**：优先 **DeepSeek-R1 8B** vs **Qwen 4B** vs **当前云端模型**；Bonsai 27B 可做少量探索，但 **2.38 Token/s 的初测性能不适合被迫跑完整批次**。同一材料、同一任务、同等上下文与可比的输出预算；记录模型、量化格式、运行环境和实际生成参数。
- **第一轮方法**：每个模型先做**单轮提炼/归纳**基线，再给一次明确的审阅意见做**一轮修订**。反馈可来自人工/人工标注或独立证据审校；不默认“模型自己批评自己”等于独立监督。后续再决定是否尝试自评、多轮循环或不同模型担任 Critic。
- **评测维度**：原文忠实度、主要论点覆盖与遗漏、区分引述和推断、引用/出处可追溯性、事实或文义幻觉、有价值的新观察、批评是否抓住真实弱点、**修订前后净改善和新引入错误**；同时记录 TTFT（可得时）、总耗时、生成 Tokens、可用 RAM/Swap、云端 API 成本（若可得）。不得仅让同一个模型主观打分代替复核。
- **样本输出**：保留原文锚点、输入提示、初稿、批评反馈、修订稿、人工或独立审查意见及耗时，用版本化/可回放的最小格式保存；私人或受限版权文本、模型权重不提交公开仓库。

## 最小执行与验收

- [ ] 选定 3～5 段合法且可人工核对的词话/评论文本，记录底本、卷则及最小关键观点。
- [ ] 确认 8B 完整生成**最终答案**（之前短 Smoke Test 的 96 Token 全被 `<think>` 用掉，不能拿它当质量证据），稳定控制推理/输出 Token、避免 OOM/大规模 Swap。
- [ ] 固定一次性提炼的任务与输出格式，对照 8B、4B 和云端基线；记录材料、回答、时间、引用和错误。
- [ ] 在相同材料上做**仅一次** Critique → Revise 对照，并检查改进幅度、事实错误增减及是否只是措辞润色。
- [ ] 归纳模型角色的实际适用边界：8B 只能预整理 / 可提出候选观点 / 可做初步批评 / 可承担受监督修订，分别给出案例证据。
- [ ] 根据结果再判断是否值得引入持续 Refine 工作流、检索/工具、不同模型交叉批评或 Notebook；若收益不成立，停止扩大。
