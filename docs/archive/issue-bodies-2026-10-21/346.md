## 目的（2026-10-20）
一次性对 CNKGraph **全部已公开列出的 API 做有记录、可复现的可用性普查**，不是只测词谱，也不是仅做 3–5 个代表性案例。把可用能力和实际响应结构完整整理，判断哪些能被 Poeticus 使用：实时 API、受许可的本地缓存／结构化数据、仅作为研究参考、暂不可用。关联 #184 资源复用总账本。

## 全面盘点（范围不能缩回格律）
- [ ] 保存官方 Postman 版本、下载时间、SHA 与示例 manifest。**逐条展开 71 个示例**，归并同 HTTP 方法+路径的重复请求但保留各自输入变体和测试状态；检查是否有更新的 Swagger / 官方文档端点。为全部 12 类逐项出一份覆盖表。
- [ ] 针对每条可安全执行的 Postman 请求做**低频、串行、只读** Smoke Test，实际记录 URL 模式、方法、脱敏请求体示例、HTTP 状态、响应类型／数据规模、必要字段、语义是否正确、异常／超时、耗时、是否需要登录、可定位的原始文献/实体 ID。即使返回 HTTP 200，也必须检查是否是有效业务结果。各 API 至少有一例业务有效输入；遇未登录、超限、失效或高数据量风险，记为阻塞/不可验证，不绕过限制、不批量下载全文。
- [ ] 对返回数据做分类：**可用（有样本、字段符合）／部分可用（输入或覆盖受限）／不可用（404等）／需认证／本轮未能验证**。允许旧文档结论被新实测推翻；记录实际调用时间和版本。
- [ ] 与 [CNKGraph 开放资源及使用条款](https://cnkgraph.com/Home/OpenResources) 对照授权，区分**个人研究实验、按需 API、缓存、批量本地持久化、商业/公开服务**。官方研究学习 API 有**非商业使用限制**：未经授权不得镜像或直接面向生产用户开放；不要将网页可读等同于数据可自由再分发。
- [ ] 对全部**确认可用的能力**建立 Poeticus 的候选能力表（domain / API / request schema / response schema / 示例 / 关联实体 / 价值 / 失败处理 / 授权状态 / 接入建议），给未来按需复用。能够合法落盘的仅保存有出处、版本、许可说明的适量结构化数据；其余优先记录接口描述、脱敏测试结果与不包含大段版权文本的 fixtures。

## 优先验证但不限制为这些
- 词谱 `/api/ciTune`、`/api/ciTune/{id}`、`/api/ciTune/find`、`/api/ciTune/pattern`；韵典 `/api/rhyme/...` 与 `/api/rhyme/find`；诗文 `/api/writing/{id}/tones`／`bookLinks`、作品与全文查询。
- 词汇与典故、字典、人物 ID/别名、古籍版本/卷定位、年历换算、地理关系、类书条目、曲谱与其他工具。**不要因当前诗词功能用不上就跳过接口普查**。
- **LLM 格律分析最短试验**：取真实词谱结构 + 指定词作原文 → LLM 解释句数、片段、韵位、平仄；人工检查变格、入声和多音，先验证可用性，不要求自建词谱识别引擎。

## 交付及验收
- [ ] 12 类**全部列出**；71 条示例**全部有结果或明确阻塞原因**；重复路径汇总出独立端点数；任何新增官方文档端点另列，不假装覆盖未知私有 API。
- [ ] 机器可读 manifest 和人类可读能力矩阵/研究报告，在 Poeticus `docs/research/` 或适当目录；只提交安全的元数据与代码，不提交受限正文、凭据或整个第三方数据包。
- [ ] 对可用能力输出完整「可直接调用/可有限缓存/可合法入库/暂不接入」清单，并列出潜在产品 Tool 与已有 `search_documents`、`lookup_allusion`、`lookup_reference` 的边界。**不按 API 一对一新增 71 个 Agent Tool**，不因接口跑通就自动上线。
- [ ] 真实调用日志（脱敏）与最小 Contract Smoke、质量/许可/成本风险清楚；相关实验结果回写 #225（词律）、#238（人物关系）、#24（词典注释）、#184（资源总览）。整个普查可以分阶段执行，但不能把“只跑词谱”当完成。
