## 背景（2026-10-08，陆游 / 杜甫 Case 后的设计复盘）

用户提出：**朝代标签是否应该保持宽松，让 Agent 结合作者生平和文学文本判断先后，而非继续增加辅助性朝代规则？** 本 Issue 是职责边界评估，不预设需要修改代码或取消全部规则。

本次陆游《鹧鸪天》其六 ↔ 杜甫《小寒食舟中作》的强对应之处，是「双双新燕飞春岸，片片轻鸥落晚沙」和「娟娟戏蝶过闲幔，片片轻鸥下急湍」的措辞、句式和意象，不是“杜甫生于唐、陆游生于宋”这一项即可证明化用。**时间信息用于限制可能方向，不能替代文本和来源判断。**

## 当前实现（已查代码）

- `backend/retrieval/chronology.py`：`DYNASTY_PERIODS` + `classify_dynasty_relation` 返回 `clearly_earlier / clearly_later / same_dynasty / overlapping / unknown`；
- `backend/retrieval/eligibility.py`：只硬排除 `clearly_later` 与已确认 self-hit；同朝、交叠、未知均保留，不做精细年份判断；
- `backend/retrieval/serving.py`：当传入 `dynasty=null`，先尝试 current-work aliases 的 Corpus 朝代标签，再以同作者 Werneror 标签计数推断；无法可靠推断时保留 unknown；
- Werneror 某些五代 / 南唐词人会被标为「唐」，并非可靠历史断代。公开作品库目前亦无可靠逐首 dynasty。

因此现行策略**不是“所有非严格前代都排除”**，但它仍会根据有误差的来源标签硬丢弃 `clearly_later` 候选，并为缺少朝代元数据的当前作品额外做推断。

## 待回答

1. 对 **textual provenance** 问题，是否有必要在 Retrieval 阶段硬过滤明确晚出的记录？此规则带来的 Top-K 净化是否抵得上错误标签导致的误删？
2. 当请求无可靠 dynasty，是否优先**不推断 / 不硬筛**，保留候选及其原始 dynasty，交由 Agent 判断？当前 `author_corpus` 与 `current_alias` 推断有没有额外误判？
3. 模型一般知道杜甫早于陆游，但对生僻作者、同朝先后、南唐/五代等知识可能不稳定。何种情况下应依赖确定性高可信元数据，而不让 Agent 凭记忆猜年代？
4. 如果未来补充作者生卒年或具体作品编年，是否只作为证据字段提供给 Agent，而不是继续膨胀过滤规则？
5. 任何选择都不能用“后世记录占满 Top-K”作为隐性理由牺牲真实前代召回：应有对照数据而非偏好争论。

## 建议最小验证（不预设实现）

在同一代表性 Case 集上对照：

- A：现行 `clearly_later` 过滤 + dynasty fallback inference；
- B：保留所有非 self-hit 候选，附原始 dynasty / unknown，Agent 做先后与文学关系判断；
- 可选 C：**仅对可信度已核实的时间元数据**进行极小范围 hard filter，其余 unknown 不硬筛。

观察：目标前代文本 Recall / eligible rank、Top-K 后世噪声比例、Agent 是否错误断言先后或化用、调用成本和回答质量。至少纳入：陆游→杜甫、同朝作者关系、五代/南唐标签偏差、当前请求 `dynasty=null`、少见作者，以及“非前代候选很相似”的负例。

## 暂定边界

- **文学判断由 Agent 完成**；Retriever 只提供带来源身份的文本候选和低风险辅助信号；
- 不把 dynasty label 当成历史考证成果；未知宁可明确 unknown，不靠硬编码“猜精确年份”；
- 不急着删掉一切 `chronology` 代码，也不因为一个 Case 堆更多映射；
- #151 处理同作品重复；#173 处理题名/正文归属；#174 处理候选上下文、引文忠实度和文学比较。本 Issue 只讨论时间处理策略。
