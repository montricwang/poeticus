## 背景与目标

关联 #311（Critic 研究主线）、#148（Persona / Skills / Library / Notebook）、#312（自主阅读）、#314（评测）、#341（文献提炼 Refine 前置验证）。2026-10-19 的讨论提出把 Hindsight、LangMem、A-MEM、MemOS、PersMem 等研究机制融合到**同一个** Critic Notebook，而不是同时部署五套有重叠写入语义的框架。

目标：让 Agent 能保留过去如何形成与修订观点的历史，同时只使用当前可审查、可溯源的知识摘要；记忆管理本身须能被测试和回滚。

## 技术归属与候选机制

- **四层不变**：Persona/Constitution（稳定且审阅）、Skills（方法）、Library（有来源外部材料）、Notebook（评论者自身研究经历/假说/观点）；与 #45 的用户记忆隔离。
- **Hindsight**：Retain / Recall / Reflect 以及事实、经历、观察、观点区别；借鉴交互设计，先不让外部服务成为第二记忆权威。
- **LangMem**：后台巩固/去重的调度思想，未来以一个可控 Worker 对 Notebook 的候选层工作。
- **A-MEM**：札记间的显式链接（原文证据、支持、反驳、衍生），首版只保存引用关系，不急于图数据库。
- **MemOS / skill evolution**：跨经历积累方法的候选，再经独立评测后晋升 Skill；不自动改写 Persona。
- **PersMem**：兴趣、惊讶、不确定性等*标注/检索策略*的候选，单独 A/B 实验，不能用情绪分数替代证据可信度。
- **事件溯源**：不可变事件为事实记录；当前观点、压缩摘要、关系索引只是可重建投影。观点撤回是追加事件，不得修改旧纪录。

## 首版隔离原型（与 #341 互不阻塞）

- [x] 独立研究目录提供可运行的 SQLite append-only 事件记录（提出/质疑/修订/撤回），不同 claim 的版本与外部证据锚点。
- [x] 从事件历史重建**当前观点候选**，提供按关键词召回与候选巩固摘要；整理结果标注是派生内容，不充当外部独立证据。
- [x] 人工或独立验收后才可将候选晋升；线上 Agent 不读取、不写入实验数据库，不接入 #45。
- [x] 用确定性测试覆盖无法覆盖历史、撤回、跨 claim 独立性、无证据不能晋升、摘要可重建。
- [ ] 用 #341 的合法文献样本做第一轮真实内容评估；观察幻觉、旧意见回灌、记忆膨胀和长时间质量。无实测不得声称形成品味。

## 不做

不同时安装五套 Memory Framework；不把自动摘要视为自动形成品味；不把 LLM 生成的观点用作独立文献证据；不引入线上读写、定时自动研究、主观情绪模拟或 Persona 自动修改；不打断 #311 P0 独立判断与文风开发。

## 2026-10-20｜优先复用成熟框架，不以自研原型绑定生产架构

用户决定后续采取「拿来主义」：长期记忆首先比较成熟框架/现成接口，优先验证 **Mem0、Hindsight、LangMem**（其他候选可视需要加入）；记录许可证、维护状态、存储后端/依赖、与现有 LangGraph/PostgreSQL/pgvector 的接入和退出成本。**不同时安装全部框架，不因 Star 数高就预设准确率**。

本 Issue 的 SQLite 事件日志只是理解观点版本与溯源的隔离实验，不能在未对照成熟项目之前成为线上 Memory Service。用户长期记忆 #45 共享适用的检索/巩固基础能力，但必须采用独立身份边界、可真实删除的数据生命周期；Critic 候选审阅/研究历史另走 #148/#311 规则。

选型首轮只需最小端到端试验：记录一条用户偏好→另一场会话召回→修订/撤回→删除后检索不到；另测 Critic 的「文献证据→候选判断→修订历史」。得出可复用的接口边界再决定是否取用 PR #348 原型中的部分代码。未做真实文学质量 Eval 不宣称形成品味。
