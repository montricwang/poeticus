## 2026-10-03：PR #69 本地验收新发现——先验证列值，再确定数据修复范围

用户在 React 阅读器选到原书题头「翦朝霞 / 思越人　牡丹」时，看到**大标题「思越人·牡丹」**、小字「贺铸 · 寓声：翦朝霞」，要求把该案例列入后续数据校正。

**证据区分：页面显示「思越人·牡丹」尚不能证明数据库的 `cipai` 错误**。截至目前，当前前端 `poemTitle()` 会把 `cipai` 与 `title` 自动拼成 `cipai·title`，即使数据库三列已经正确分离，也会得到同一显示结果。与此同时，现有 EPUB 解析代码 `interpret_heading()` 已包含贺铸「原调 + 全角空格 + 作品题注」的拆分处理。不可把早期抽取阶段的缺陷结论不加核查地等同于现有 PostgreSQL 状态。

**后续复核步骤（在本机执行，不公开私有源文）：**

~~~sql
SELECT id, source_order, author, cipai, yusheng_title, title, review_status
FROM poems
WHERE author = '贺铸' AND yusheng_title = '翦朝霞';
~~~

期望文学语义为：

| 字段 | 值 |
|---|---|
| `cipai`（原词牌） | `思越人` |
| `yusheng_title`（贺铸寓声） | `翦朝霞` |
| `title`（独立题注/作品题目） | `牡丹` |

- **若查得三列均符合预期：** 本例的主要剩余问题是前端题头展示层级，由 [#68](https://github.com/montricwang/poeticus/issues/68) / Draft PR #69 修复；不得为修 UI 擅改正确数据库数据。
- **若有一列仍混写、遗漏或归错：** 本 Issue 负责继续追溯来源 XHTML → 导出 JSON → 入库记录，以最小、带审计记录的更正修复，不批量覆盖 UUID、来源证据或已读版本；合成回归测试和本地校验一并补齐。
- 贺铸其他相同排版题头仍按原任务抽样审计，**当前不关闭 #60**。

**与显示契约区分：** 词牌、寓声、题目、词序、作者应保持独立数据字段；当前展示采用“词牌在第一行（旁边小字号寓声）—下一行题目—再下一行作者”，这是 #68 的 UI 决定，不能以数据库拼接来实现。

## 背景（2026-10-02 全量 JSON 导出后发现）
目前 EPUB importer 已能导出 15 册、3491 首候选词作，ID 唯一、无空正文；但这三项不变量**不能证明词牌/词题的语义分界准确**。用户在人工抽查贺铸词集时发现：
- 《半死桐》题头带「思越人，亦名鹧鸪天」，目前主要词调记录为 `思越人`，而「鹧鸪天」未进入中间 schema。这是目前针对该来源有意不维护完整词牌别名体系的取舍，**不是须立即补 `cipai_alias` 字段的 bug**。
- 《翦朝霞》源书题头含「翦朝霞 / 思越人 / 牡丹」，当前输出虽能识别 `思越人` 为词调，却把「翦朝霞」与「牡丹」混写为一条 `title`。这会把 **贺铸自拟的寓声名** 与作品的独立题注混为一谈，属于语义归类问题。

## 外部核验线索（具体版本差异需再与本地 EPUB 逐字核对）
- 《贺铸词集校注》（钟振振校注）目录在该处列出「半死桐 / 思越人，亦名鹧鸪天」以及「翦朝霞 / 思越人 / 牡丹」。出版物的目录可作为结构比对线索：https://search.megbook.com.tw/mall/detail.jsp?proID=3992389
- 《全宋词》在线录文采用「翦朝霞（牡丹同前）」；其中「同前」是对前一个调名的继承式标注，不应作为这首词的题目保留：https://ctext.org/wiki.pl?chapter=17670&if=en&remap=gb
- 龙榆生《唐宋名家词选》指出贺铸常为旧词调另拟寓声名，例如《半死桐》：https://longyusheng.org/ci/hezhu/index.html

## 建议的后续工作（不阻塞当前 PR）
1. 针对**整册贺铸**审计该类题头是否成簇出现，不仅搜字面「亦名」；识别独立词题/花题与寓声名之间的差别。不要只针对《翦朝霞》打一个字符串补丁。
2. 保留最少语义：`tune = 思越人`，`title = 牡丹`；「翦朝霞」另记为 **原书寓声名/来源标题证据**（字段或来源审校记录待定），而不是与「牡丹」拼成一条作品标题。
3. 先评估现有两个字段是否足以支持 MVP 读诗，以及源位置/原题头是否可追溯；如确需新字段，设计可选且适用于多来源的语义表示，不为了此例立即增加全书必填 `cipai_alias`。
4. 在 `scripts/corpus/epub_import/extractor/rules.py::interpret_heading` 和 `extractor/extractor.py` 检查拆分依据；增加**纯合成**的贺铸题头回归测试（含「亦名」、三个片段、原调名继承），在私有 EPUB 里复核，再跑全册预检/导出。
