## 背景与依据

2026-10-12，通过已接入 ChatGPT 的 **Poeticus Browser（Playwright MCP）** 在 Poeticus 公网版以 **390 × 844 CSS 视口**实际检查手机阅读页与阅读讨论页，截取页面、读取 DOM 并操作「打开阅读讨论／返回阅读」。本单记录用户确认的下一轮移动端 UI 微调方向，**尚未修改代码**。

当前观察：
- 阅读页右下角「对话」悬浮按钮贴近屏幕底部；不遮挡短词，但与移动浏览器底部工具栏／系统手势区域可能产生空间冲突。
- 讨论页第一行是「← 阅读讨论」，第二行才是「对话 / 赏析」切换，形成两层导航；空对话时第二层尤其显得疏离。
- 当前公网界面与开发分支可能不同；实现前以目标分支真实代码和可运行页面为准。

## 已确认的设计方向

### 1. 阅读页：「对话」入口小幅上移

- 保留右下角固定的轻量悬浮按钮，不改成自由拖动的悬浮球。
- 先试 **比当前约高 30–50 CSS px** 的方案，最终距离根据 safe area、浏览器底部工具栏、滚动和视觉平衡实测决定；数字是试验起点，不是不可变规格。
- 继续避免遮挡诗词正文、选区手柄、底部「上一首／下一首」导航等内容。
- **暂缓自由拖动**：目前没有明确遮挡需求，拖动会与滚动阅读、文字选择和触摸手势竞争。

### 2. 手机讨论页：合并成单行顶部导航

目标结构：

```text
〈 阅读                         对话   赏析
──────────────────────────────────────────
```

- 顶栏**左侧为明确可点击的「阅读」／「返回阅读」**，保留返回箭头；点击回到诗词阅读页。不再把「阅读讨论」这个当前页标题伪装成返回按钮。
- 顶栏**右侧为「对话 / 赏析」切换**，保留明确的选中状态、合理点击热区和键盘／屏幕阅读器语义。
- 移除移动端独立占据第二行的重复视图切换栏；不必机械保留现有长下划线，可沿用现有简洁编辑式视觉语言。
- 只针对窄屏布局收口，不擅自改动桌面两栏讨论工具栏及生成赏析的业务动作。

## 验收清单

- [ ] 320 / 390 / 430px 手机视口下，顶栏左侧返回与右侧两项切换均可见、可点击，不挤压或换行失控；深浅主题正常。
- [ ] 阅读 → 对话 → 赏析 → 对话 → 返回阅读；切换前后的作品、已有消息、已选视图等状态保持预期。
- [ ] 阅读页悬浮入口在页面顶部、诗文末尾、正文滚动、底部导航附近都不遮挡关键文字和交互；含移动端 safe area、浏览器底栏和软键盘变化。
- [ ] 触摸目标大小、键盘可操作性、焦点状态、语义标签和返回路径可用；不干扰划词引用与系统选区手势。
- [ ] Playwright 复查 DOM、视口、交互和 Console；**实际手机或浏览器视觉验收仍需人工确认**，不能只看 CI。
- [ ] 不修改后端 API、语料、对话／赏析业务数据流。
