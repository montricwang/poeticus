## 目标
让 Poeticus 对词人、评论家、别名、年代、官职、籍贯、交游等进行可追溯的**实体查询**，避免依据模型记忆编造关系。比较通用知识图谱与专业 CBDB 的增量。

## 候选
- Wikidata MCP 项目与服务入口：https://www.wikidata.org/wiki/Wikidata:MCP （逐项核实服务可用性、数据覆盖与官方归属）。
- CBDB 社区 MCP：https://github.com/cclintw/cbdb-mcp-server-codex （**非 CBDB 官方**，需要本地 CBDB SQLite）；官方数据入口 https://cbdb.hsites.harvard.edu/cbdb-api 。
- 基准：Wikidata 原生 API / SPARQL、CBDB 自有 API / 数据库查询。

## 最小实验
- [ ] 3–5 个真实人物及同名/别号 Case（如 姜夔/姜白石/白石道人、张炎等），分别查询实体 ID、别名、年代、籍贯及文献来源。
- [ ] 对照实体歧义、交游与关系方向、source/reference 是否存在；记录历史时期覆盖和缺项，不因图数据库有边就认定史实已证。
- [ ] CBDB 先调查数据库版本与授权范围、官方 API 可用性及第三方 MCP 项目权限；不先下载/公开整个库。
- [ ] 比较 MCP、原生 API、PostgreSQL 少量关系表的额外价值与成本，决定是否作为补充证据源。

**停止线**：不启动 Neo4j，不自动写入 canonical 人物图谱，也不公开第三方受限数据。

### 2026-10-12｜补入 CNKGraph 与国家图书馆知识图谱作为必要基线

**本轮用户提醒**：原 Issue 的主要对照只有 Wikidata 与 CBDB，尚未明确列出 **CNKGraph 自有的人物/关系知识图谱**。Poeticus 已经使用 CNKGraph 的部分典故/出处 API，但**不能推定人物身份、别号、交游、时空、引用关系等其他数据字段已经实测过**。新增同场对照，不能将「CNKGraph 已接部分 API」误当「整个知识图谱已接入」。

**新增必须检查的已有资源**：
- [ ] [CNKGraph](https://cnkgraph.com/) / [Open API](https://open.cnkgraph.com/swagger)：先阅读人物/关系/事件/出处端点、实际字段与 id 体系，随后以姜夔、张炎、苏轼等同一人物组对比 Wikidata 与 CBDB 的别名、年代、籍贯、交游和 source；以 **Poeticus 现有 `lookup_allusion/lookup_reference`** 作已知能力基线。官方研究 API 有非商业限制，新增用途需另行核对。
- [ ] [国家图书馆中华古籍智慧化服务平台](https://guji.nlc.cn/)：该站公开导航具有『知识图谱』『知识检索』『图谱可视化』『元数据图谱』模块（官方站点自述、**尚未亲自调用具体人物图谱/证据 API**）。核对它究竟提供可访问的结构化关系、可追溯记录还是仅网页可视化；不要以“图谱”命名直接视作可用于 Poeticus 的 KG 服务。
- [ ] [唐宋文学编年地图](https://poem.cnkgraph.com/)：另核人物活动、地理时间数据是否有结构化导出/授权；现有数字人文资源图已列研究入口。

**重新定义对照组**：同一 3–5 位历史人物，四种来源 **CNKGraph（现有基线）/ Wikidata（#236 API+MCP 已实测姜夔基础属性）/ CBDB（尚未实测，授权要先查）/ 国家图书馆 KG（网页存在，结构化接口待核）**。尤其分清『这个人物是谁』『与哪些人物何种关系』『哪个原文直接证明这条关系』三个输出粒度。根据实际来源覆盖决定已有 Poeticus 自建小型关系表是否仍必要，不预先启动 Neo4j。

关联 #149 知识图谱选型、#184 资源复用研究、#237 同站古籍全文来源验证。


### 2026-10-12｜CTP 数据维基亦有带文献依据的结构化关系

**本轮 #237 来源选型时观察到**：中国哲学书电子化计划（CTP）除了古籍正文与传统 API，还有 [数据维基《沈氏乐府指迷》](https://ctext.org/datawiki.pl?if=gb&res=723191) 一类结构化书目，列出 `creator`、`indexed-in` 等关系并附《四库全书总目》等文字来源；另有 [张炎 Data Wiki](https://ctext.org/datawiki.pl?if=gb&res=987527) 人物实体。它是 **#238 的补充候选**：先看书目、人物/文本出处是否具有 CNKGraph/CBDB 不具备的直接文献锚点，再考虑是否使用；**仅验证网页存在，尚未访问 CTP 关系 API**。CTP 文本 Wiki 可能有 OCR 未校内容，关系带出处不保证边真实。
