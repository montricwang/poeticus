## 背景

Poeticus 已经出现三种不同的作品关系来源：

1. **Text Space**：#119 的 Dense / BM25 / Hybrid Retrieval；
2. **Poetics Space**：待建立的作品诗学画像；
3. **Knowledge / Criticism Graph**：#149 规划的评论家、文献、概念、作品关系。

这些“接近”不是同一种接近。

例如：

- 两首都写秋夜思乡，文本 / 语义空间可能很近；
- 两首题材完全不同，但都呈现“清空、疏宕”，诗学空间可能很近；
- 两首作品未必文本相似，但历代评论经常把它们放在同一概念或比较关系下，批评史空间很近。

因此不应寻找唯一的“诗词相似度”。

## 核心判断

> Poeticus 应允许多种文学距离并存，再按具体产品任务组合。

候选视图：

~~~text
Text / Semantic View
→ 写了相似的东西、使用了相近的词句 / 意象

Poetics View
→ 写法、气质、风格维度相近

Criticism / Graph View
→ 在文学批评史中被放到了一起
~~~

机器学习上可参考 multi-view representation / multi-view similarity，但本 Issue 不预设必须采用某个复杂 multi-view clustering 算法。

## 第一阶段产品问题

优先研究“近邻 / 排序”，而不是一上来做全库自动聚类。

### 1. 文本相近

直接复用 #119：

> 与当前作品在语义、句法、意象或文本来源上值得比较的作品。

### 2. 风格相近

使用 Poetics Profile：

> 题材不同，但清空 / 密丽 / 疏宕 / 豪健等画像接近。

### 3. 批评史关联

使用 #149：

> 历代评论家、文献或词学概念将这些作品 / 词人建立了显式关系。

### 4. “意外近邻”

特别值得实验：

~~~text
Text distance 较远
+
Poetics distance 较近
~~~

即：

> 写的完全不是一回事，但为什么读起来气质相近？

这可能比普通“猜你喜欢”更有 Poeticus 的产品辨识度。

## 相似度组合

第一版不要提前固定公式：

~~~text
Similarity =
w_text * text_similarity
+ w_poetics * poetics_similarity
+ w_graph * graph_relatedness
+ ...
~~~

不同入口应有不同权重甚至不同算法：

- “相似诗句” → Text 权重大；
- “风格相近” → Poetics 权重大；
- “批评史上的同路 / 对立” → Graph 权重大；
- 首页推荐 → 可能同时考虑作品质量、去重、多样性与用户最近阅读，不等于单纯最大相似度。

因此不要先设计一个全局万能 score。

## 聚类的地位

Poetics Profile 确实可以形成一种“人为定义坐标轴后的聚类”：

~~~text
作品
→ 清空 / 密丽 / 疏宕 / 沉郁... 可解释向量
→ 距离
→ 聚类 / 近邻
~~~

但产品第一阶段更应先验证 **nearest neighbors / ranking 是否合理**。

原因：

- 聚类强迫每首作品进入某个全局结构；
- 古典诗词风格往往连续、交叉，不一定自然形成稳定簇；
- 首页推荐和“与此词相近”只需要局部近邻；
- 如果局部距离都不可信，全局聚类只会把错误画得更漂亮。

聚类、UMAP / t-SNE 可视化、community detection 等放到后续探索。

## 最小实验

在 Poetics Profile 的 50～100 首样本上构造三类近邻：

1. Text nearest neighbors；
2. Poetics nearest neighbors；
3. 混合 nearest neighbors。

人工检查：

- 三组结果实际分别“像在哪里”；
- 是否出现只是作者相同 / 词牌相同造成的伪近邻；
- 风格相近是否能跨题材发现合理作品；
- 混合结果是否只是把三个弱信号平均掉；
- “意外近邻”是否真有阅读价值。

## 第一阶段不做

- 不重新训练 Embedding 模型；
- 不因为 BERT-CCPoem 存在就立即替换 #119 当前 Qwen Embedding；
- 不固定唯一文学 similarity score；
- 不直接上线自动聚类页面；
- 不把 cosine similarity 解释成“文学相似概率”；
- 不把 Knowledge Graph path length 简单解释成审美距离。

## 停止线

第一阶段只验证：

> **不同视图是否真的给出性质不同、且各自有阅读价值的近邻结果。**

如果三个视图最后总是返回同一批作品，就没有必要增加 multi-view 复杂度。

## 2026-10-12｜高维多标签索引也可实现主动文学旁征博引

用户强调想要的是 **Poeticus 自己从大量作品中发现遥远、细微、可解释的共同感受**，而不是用户手动给 A/B 两首后 LLM 比较；优先发挥 #156 的大规模开放标签/特征积累，**无需每次问答都先让 LLM 重读全库**。



可比较的候选路线：`批量 LLM → 高维稀疏文学特征` 建索引 → 对当前词生成同类特征 → `标签倒排/布尔匹配/加权 Jaccard/稀疏 cosine` 召回；再与 #119 dense/BM25、#149 批评史关系等候选合并，最后由 LLM **解释细微共同机制与关键差异并给出实际文本证据**。不强制依赖完整 KG，也不把一篇作文的全部细腻感受压到『清空=True』。



**标签数量不是最终相似度真值**：普通标签（秋/月/怀古）出现很频繁，不能和罕见的表达机制标签一票等价；大文本/长调天然标签更多，需长度归一化、权重（IDF/语义重要度）、同义合并和去重。可对共同标签数量、加权 Jaccard、稀疏余弦和 Dense 近邻做离线排序对比；同时专门找`字面/题材不似，但修辞或审美感受相近`的意外近邻，检查是否有实际文学价值，防止空泛地把两首都说成『人生无常』。



**优先把解释证据锚到具体诗句**：共享标签作为候选提示，不自动证明文学影响或化用；若候选只是模型批量打出来的臆测，要允许丢弃或指出依据薄弱。标签库与 #148 Critic Notebook 可以互相提供候选思考材料，但**批量标签不能直接自我强化为 Persona 最高原则**。



**增量规模试验**：#156 先小样本打标，再选 10–20 首起始词自动发现 Top-K，人工盲测比较 sparse-tag-only、dense-only 与 fusion 哪些真产生了有解释价值的新作品。成功后再评估几千首离线生成，不直接启动全库批处理。
